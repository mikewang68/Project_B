# PSMS 与 WMS 入库联动评估及资料确认清单

评估日期为 2026 年 11 月 3 日。供 PSMS 负责人李润泽、WMS 负责人周绪敬和项目负责人确认首期联调。

## 可行性

**可以做，现有两套系统都有可复用的业务入口。跨系统接口、状态同步和流程卡点仍需双方开发。** 首期可在服务器隔离环境选一条卸车工单，走通「PSMS 派发 → WMS 确认仓库并建单 → PSMS 安排转运 → WMS 分批收货并回传 → PSMS 入库复核」。一条任务关联一个目的仓和一张 WMS 入库单，仓库由 WMS 确认，双方各自写入自己的数据库。

| 模块 | 已有基础 | 首期需补齐 |
| --- | --- | --- |
| PSMS | 派工看板支持卸车工单，后端已有工单命令、作业区校验和完成前的关联任务检查 | 物料明细与派发入口、任务关联与待发送记录、回执接口及进度展示。WMS 确认仓库后才允许安排对应转运，收齐后才满足入库复核条件，工单完成仍检查其他前置任务 |
| WMS | `StockinService.java` 已有建单和实际收货事务，支持 `CUSTOM` 来源，按公司、仓库、货主限定业务范围 | 到货任务接单与查询、选仓建单、PSMS 任务号关联、收货事务内生成待回传记录。入库来源沿用 `CUSTOM`，关联记录单独标明来源系统为 PSMS |
| 铁路模拟 | 现有执行器会自动推进到入库复核完成 | 首期用明确标为联调的工单手动派发。若后续使用模拟执行器演示联动，单独配置联调模式，使其等待 WMS 回执 |

本次核对了负责人提供的实施说明和当前工作区源码。源码中未发现说明列出的三个集成接口。此前已通过 SSH 核实 node6 上的 PSMS 服务运行。本次尚未核实 WMS 联调实例及双向网络。说明中的 node6 源码目录是代码位置，WMS 仓库部署手册以 node4 为应用部署示例，实际联调地址由周绪敬或项目负责人确认。

## 接口与状态需对齐的细节

- 负责人说明建议 PSMS 通过 `POST /api/v1/integrations/psms/inbound-tasks` 派发，通过 `GET /api/v1/integrations/psms/inbound-tasks/{taskId}` 对账，WMS 通过 `POST /api/integrations/wms/inbound-events` 回传。请双方提供派发、查询、仓库确认、部分收货、全部收货和异常的报文样例。
- 同一派发或回执超时后沿用原任务号、事件号和内容重试。接收方对重复事件返回原处理结果，对同一事件号内容冲突给出明确错误。收货进度按任务序号应用，缺号时暂存并对账。
- WMS 受理任务、确认仓库、库存实收是三个独立节点。双方需明确入库单号、仓库和逐行累计数量何时返回。短收、超收、错料及人工结案进入差异处理，入库复核以实收收齐回执为条件。首期派发后变更或取消由人工协调。

## 服务器联调验收

1. 派发一条 100 捆钢材的卸车工单，核对 WMS 待确认任务、PSMS 受理状态及零库存变动。
2. WMS 确认仓库并建一张入库单。PSMS 显示对应仓库和单号后，安排转运。
3. WMS 先收 60 捆再收 40 捆，核对两次库存流水及 PSMS 的逐行实收进度。收齐后验证入库复核，其他前置任务也满足时完成工单。
4. 重发派发与回执，并复测重复提交同一次收货，核对只有一张关联单、库存总增量 100 捆。另验证无效物料、错误单位、越权仓库以及断网后的回执补发。
