## 删除与有效性规则

所有 PSMS 业务主表和子表增加 `valid SMALLINT NOT NULL DEFAULT 1 CHECK (valid IN (0, 1))`。旧记录迁移后默认有效。

```sql
-- 普通业务查询
SELECT * FROM plans WHERE valid = 1;
-- 标记记录为无效，保留原数据
UPDATE plans SET valid = 0 WHERE id = $1 AND valid = 1;
-- 运维按需查看历史，无需恢复记录
SELECT * FROM plans WHERE valid = 0;
```

通用表访问层默认过滤有效记录；列表、详情、更新、计数、子表读取和报表均遵守该规则。`deleteMany`、兼容的 `truncate`、审计过期清理、任务重新生成和演示重置都不发送物理 DELETE/TRUNCATE。

替换子表时将旧行标记无效，新行使用 `row_version` 和有效行唯一索引，避免保留旧行后发生主键冲突。任务重建使用新 ID，旧任务及其依赖/班组子行保留。批量替换在事务中完成，插入失败会回滚旧代次的失效操作。

数据库演示重置保留账号和审计，将旧业务记录标记无效，再用带代次后缀的新主键写入种子；设备的物理标识保持稳定。字段名 `dropped` 为旧接口兼容字段，现在表示被标记无效的表，新增 `invalidated` 字段用于明确语义。前端任务重新生成/拆分/合并也保留被替换记录，并从页面和统计中过滤无效项。

## 配置与运行

前端：进入 PSMS 后运行 `pnpm dev`，或 `pnpm build` 后运行 `pnpm preview`，预览入口为 `/production-dispatch/`。

真实数据库更新属于表结构迁移，不是数据搬家。`PSMS/backend/src/db/migrate.ts` 在事务中应用结构变更，并检查已有列，支持重复运行；本次未实际执行。后端默认开启 `OPENGAUSS_AUTO_MIGRATE`，正式启动新版本前应在测试库验证，再按项目的数据库变更流程安排应用；关闭该开关可改为手动运行 `pnpm db:init`。手动命令还会执行既有的时序库初始化流程，参数以当前 `.env` 为准。

大模型通过后端 `.env` 配置以下三项，然后重启后端：

```dotenv
AI_BASE_URL=https://your-provider.example/v1
AI_MODEL=your-model
AI_API_KEY=your-server-side-key
```

接口遵循兼容的 `chat/completions` 格式。UI 中选择“大模型分析”并登录业务服务后使用；未配置或未启动后端时明确显示本地规则模式。生产托管需将同源 `/api/*` 代理到 PSMS 后端；本地开发与预览已配置代理至 `127.0.0.1:3100`。

数据库迁移按 [openGauss 6 ALTER TABLE 官方文档](https://docs.opengauss.org/en/docs/6.0.0/docs/SQLReference/alter-table.html) 和 [CREATE SEQUENCE 官方文档](https://docs.opengauss.org/en/docs/6.0.0/docs/SQLReference/create-sequence.html) 核对：通过查询系统目录实现列迁移幂等；子表版本列先增加常量默认值，再设置序列默认值。仍需实际 openGauss 环境验证 DDL。
