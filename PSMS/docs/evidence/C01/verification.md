## 5. TypeScript 诊断边界

额外执行了非封板命令 `tsc --noEmit --pretty false`，结果为退出码 1。加入标准 `src/vite-env.d.ts` 后，剩余错误均来自权威 `package-baseline.json` 未包含 `@types/react` 和 `@types/react-dom`，导致 React、React DOM 与 JSX 声明缺失。

原任务要求依赖必须与机器基线完全一致，并明确禁止私自新增包；固定脚本和完成命令也不包含 `typecheck`。因此 C01 未伪造宽泛声明、未关闭检查、未越权增加依赖，也不声称独立 `tsc` 通过。C02 开始前应先提交依赖基线修订建议，批准精确的 React 类型包版本并增加正式类型检查门禁。

## 6. 端到端与评审缺陷闭环

1. 初次运行因本机缺少 Playwright Chromium 运行时而失败；随后按权限规则安装固定浏览器组件并验证宿主要求。
2. 首轮真实浏览器验收发现 Ant Design 6 将 `Space direction` 记录为错误级废弃警告；生产代码已改用 `orientation`。
3. 双视口汇总用例初始受 Playwright 默认 30 秒上限影响；已将该汇总用例的合理上限设为 120 秒。
4. Windows 下 Playwright 内置子进程服务器清理会滞留命令管道；测试改为在 `globalSetup` 中用 Vite API 启停服务器。单用例探针和最终 14 用例均能正常返回退出码 0。
5. 独立代码评审发现 404 与错误页存在 `<button><a>` 交互嵌套；先补语义失败测试，再改为单一带 `href` 的 Ant Design 链接按钮，测试由红转绿。
6. 独立代码评审指出错误边界缺少主动异常用例；已增加懒加载抛错测试，真实断言“路由加载失败”和返回入口。
7. 截图前现在显式等待项目标题、语义化导航及 13 个导航链接全部可见，并回到页面顶部；四张证据已重新生成和人工复核。
8. 13 个页面文件不再重复硬编码编号与名称；`PageScaffold` 根据当前路径从 `routeCatalog` 读取唯一元数据。
