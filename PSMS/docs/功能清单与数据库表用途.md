# PSMS 功能清单与数据库表用途

本清单对应当前 PSMS 模块的前后端实现。所有业务记录使用 `valid=1` 表示有效、`valid=0` 表示无效；正常查询默认只返回有效记录，历史记录通过明确指定 `valid=0` 查询。

## 日志与数据规则

后端路由写操作使用 `auditOperation` 记录访问审计，业务服务使用 `writeBusinessAudit` 写入操作前后快照。审计记录写入失败只告警，不阻塞业务响应；当前实现记录在 openGauss 的 `audit_logs`，尚未接入项目统一的 WriteLog/链上合约适配器。

数据库访问层 `Table` 的 `find`、`findById`、`countDocuments`、子表 hydrate、报表聚合默认追加 `valid=1`。`deleteMany`、`truncate`、演示重置和替换子表只执行 `UPDATE ... SET valid=0`，不执行物理 `DELETE/TRUNCATE`。需要查历史时显式传入 `{ valid: 0 }`。

| `work_orders` | 核心 | 计划对应工单、资源、班组、执行状态 | `valid` |

| `equipment` | 核心 | 设备台账、作业区、通信协议、状态 | `valid`；设备标识有效唯一 |

## 当前边界

WriteLog 的统一 SDK、日志数据库地址、合约 API/认证没有随项目提供；本模块已按可配置的 REST 标准实现 `writeLog.service.ts`：先写 `audit_logs`，再投递 `WRITELOG_URL`；`plan:confirm`、`plan:recommendation`、`task:decompose`、工单执行、异常、联锁、预约、配置发布和离线合并等动作进入 `CONTRACT_API_URL` 白名单。未配置地址时状态明确为 `PENDING`，不会伪造已上链。

接口前置清单已确认：PSMS 对应调度 S1；“设备采集点”约 1,518 条，“接口连接信息”约 109 条，“跨系统交互”约 69 条，“前置确认”约 525 条，“验收检查”约 90 条。S1 采集约定包含设备编号、点位编码、值、质量码、单位和带时区源时间；当前模拟守护进程使用其中的四个代表点（EQ-IMG-01 LOAD/TROLLEY_POS、EQ-IMG-05 WEIGHT、EQ-IMG-06 LEVEL），每秒写入 openGemini `equipment_telemetry`，全流程监控页面读取并展示最新点位。

模拟守护进程：`pnpm simulate:s1` 持续发送，`pnpm simulate:s1 --once` 单批发送；服务器可安装 `deploy/psms-s1-simulator.service`。其余模块的点位字段和周期仍需接口前置清单中对应模块的具体映射，不能直接套用 S1 字段。
