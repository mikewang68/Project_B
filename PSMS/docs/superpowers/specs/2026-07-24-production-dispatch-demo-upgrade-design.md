# 生产调度 DEMO 中文化、视觉与动态演示升级设计

## 1. 目标与交付

在不改变接口契约、状态机枚举、Mock 数据结构、权限、审计与既有 `data-testid` 的前提下，升级六个生产调度演示场景：

1. 生产调度模块总览；
2. 任务自动拆解；
3. 装备与人员资源匹配、派工；
4. 超时风险与异常处置闭环；
5. 多源安全联锁锁定与恢复；
6. 弱网离线同步、冲突处理与数据合并。

最终交付包括：

- 六个完成中文化和工业科技风升级的页面；
- 五个可开始、复位、重播、自动播放的确定性演示流程；
- 一张总览 PNG、五张封面 PNG、五段 8～12 秒 H.264 MP4；
- 一份沿用现有六页结构、标题与业务价值文案的动态演示版 PPTX。

## 2. 现状与约束

- 当前项目为 React 19、TypeScript、Ant Design、Zustand、Vitest、Playwright、Vite。
- 六个目标路由均已有独立页面、业务投影、确定性 Mock、命令服务和页面测试。
- 现有六页 PPTX 使用 9 张静态界面截图；截图中可见多类英文状态、类型和内部枚举。
- 工作树存在与本任务无关的未提交修改，涉及路由冒烟值、全流程监控和公路预约页面；本设计不修改这些文件。
- 源需求文档明确要求 TOS 不绕过平台适配层直接控制 PLC/ECS 等设备，弱网与安全联锁能力仍需遵守 Mock 和生产化边界。

## 3. 方案比较

### 方案 A：统一展示映射 + 共享演示控制器 + 复用既有业务命令（采用）

- 新建纯展示层映射模块，底层枚举保持不变；
- 页面与组件只消费中文标签、语气色和可选英文编码；
- 新建轻量演示控制器，负责阶段、计时、复位、重播、自动播放和 reduced-motion；
- 五个演示流程尽量调用既有 Mock 命令服务，只有纯视觉扫描、逐步显现等阶段保存在页面展示状态中。

优点：行为边界清晰、可测试、可扩展，能保证演示与现有业务状态一致。缺点：涉及组件较多，需要系统性替换所有用户可见枚举。

### 方案 B：各页面局部翻译和局部计时

每个页面独立写状态映射和 `setTimeout`。实现较快，但易出现同一枚举多种中文、计时器泄漏和漏翻译，不满足统一映射层要求。

### 方案 C：另做纯静态“汇报模式”页面

为 PPT 单独构建五个视觉页面，不复用既有业务命令。视觉自由度最高，但会形成与真实 DEMO 分叉的第二套状态流程，容易夸大能力并增加维护成本。

## 4. 架构设计

### 4.1 展示映射层

新增 `src/presentation/businessCopy.ts`，集中提供：

- `businessCopyMap`：英文枚举到中文名称；
- `businessToneMap`：状态到 `success`、`processing`、`warning`、`danger`、`neutral`；
- `businessLabel(value, options?)`：默认返回中文，未知值返回经过可读化处理的安全文本；
- `businessCode(value)`：供详情、提示或 `title` 使用；
- `industryTermLabel(term)`：PLC、ECS、TOS、AGV、UWB 首次出现时使用中文解释。

映射至少覆盖任务目标列出的 40 项，并补充目标六页当前可见的计划、工单、异常、联锁、离线、资源和操作类型。测试要求：

- 40 项必需映射逐项断言；
- 映射值不得包含全大写枚举；
- 未知值不得原样暴露在主要标签中；
- 编码保留函数仍能返回原始值供详情和审计使用。

### 4.2 共享视觉系统

在 `src/styles/global.css`、`src/styles/theme.ts` 和目标模块 CSS 中统一：

- 背景：`#F3F6FA` / `#F7F9FC`；
- 标题与关键区域：`#0B2B50` / `#123E6B`；
- 数据流与交互：`#1677FF` / `#12B8C8`；
- 完成：`#14966D`；
- 预警：`#D97706`；
- 阻断与联锁：`#D14343`；
- 圆角 12～16px、细描边、克制阴影、8px 间距基线；
- 技术编号、追踪号、版本号降到 11～12px 和次要色。

页面采用一个主要业务工作区和少量辅助信息带，不新增炫光、玻璃拟态或与业务无关的装饰动画。1440×900 和 1600×900 下不出现横向滚动；窄宽度时用网格重排，不压缩关键文字。

### 4.3 演示控制器

新增 `src/features/demo-presentation/`：

- `demoSequence.ts`：定义阶段、持续时间和总时长；
- `useDemoSequence.ts`：运行、取消、复位、重播、完成停留；
- `DemoPlaybackControls.tsx`：开始演示、重新播放、阶段提示和“样机演示”边界；
- `demo-presentation.css`：阶段高亮、扫描、渐入、连线点亮、状态跃迁；
- `__tests__/`：使用假计时器验证顺序、总时长、重播和卸载清理。

统一约定：

- `?autoplay=1` 自动开始一次；
- 开始与重播都先恢复固定初始展示状态；
- 完成后保留最终状态；
- reduced-motion 下跳过非必要过渡，但保留业务状态顺序；
- 计时器总时长控制在 8～12 秒，开头约 0.5 秒、结尾约 1.5 秒。

### 4.4 五个确定性状态流

#### 任务自动拆解（约 10.2 秒）

`初始 → 计划确认 → 生成节点 1～4 → 点亮依赖 → 拆解完成`

- 初始态隐藏生成节点；
- 节点逐个显示，连接线同步点亮；
- 最终显示“拆解完成，可进入派工”；
- 既有生成与确认命令负责业务最终状态，展示阶段只控制显现顺序。

#### 资源状态匹配（约 9.8 秒）

`初始 → 扫描人员/装备 → 弱化不可用 → 高亮候选 → 选中推荐 → 待人工确认`

- 资源仍来自既有 selector；
- 忙碌、故障、维保、不满足资质者逐步弱化；
- 可用候选显示匹配理由；
- 最终推荐对象被选中，不自动替代人工确认。

#### 异常处置闭环（约 10.6 秒）

`超时预警 → 进入台账 → 待处理 → 处置中 → 待复核 → 已关闭`

- 复用既有异常命令与 Mock；
- 自动填入固定演示原因和处置说明；
- 最终展示责任人、处置记录、复核与关闭结果。

#### 安全联锁（约 10.8 秒）

`输入快照 → 规则命中 → 联锁锁定 → 恢复申请 → 审批 → 已恢复`

- 联锁锁定后明确禁用高风险操作；
- 复用既有触发、回执、申请、审批、恢复命令；
- 页面持续显示“规则样例/模拟状态”，不暗示真实设备控制。

#### 离线同步（约 10.4 秒）

`离线缓存 → 上传 → 版本校验 → 发现冲突 → 标记差异 → 合并 → 同步成功`

- 复用既有上传、校验与合并命令；
- 明确服务端状态优先，离线数据作为待合并证据；
- 最终显示本地版本、服务端版本和合并结果。

## 5. 页面与组件改造

### 总览

- `OverviewPage` 增强首屏业务层级；
- KPI、重点计划、风险、接口健康、货场态势全部通过展示映射；
- 保留计划号、车次、批次号，但降低视觉权重；
- 首次出现 TOS 时显示“生产调度管理系统（TOS）”。

### 任务拆解

- 上下文、任务树、资源预览、规则说明、编辑抽屉统一中文状态；
- 任务树支持阶段显现和依赖线点亮；
- 演示控制器不更改原有编辑、拆分、合并、确认权限。

### 资源匹配与派工

- 工单队列、详情、资源池、执行反馈统一中文状态；
- 资源卡增加匹配依据、不可派原因和推荐层级；
- 自动演示止于人工确认入口。

### 异常、安全、离线

- 台账、详情、证据、动作面板、状态流程与反馈组件统一消费映射层；
- 主状态显示中文，原始枚举仅在技术详情 `title` 或次要编码行中保留；
- 动画高亮当前业务阶段，不添加与业务无关的视觉运动。

## 6. 测试与验收

自动化：

- TypeScript：`pnpm exec tsc --noEmit`；
- 单元与页面测试：`pnpm test`；
- 目标页面专项测试；
- Playwright 全量与新增演示专项测试；
- 正式构建：`pnpm build`。

浏览器验收：

- 六个目标路由分别检查 1440×900、1600×900；
- 页面正文无横向滚动、遮挡、溢出；
- 主要状态、类型、严重级别和动作没有直接显示全大写英文枚举；
- 五段演示验证开始、复位、重播、`autoplay=1`、完成停留和 reduced-motion；
- 保留的英文仅限行业缩写、路由、编号、版本、追踪、审计与技术详情。

## 7. 素材与 PPT

### 素材

通过 Playwright 以 1600×900 无浏览器 chrome 模式生成：

- 总览最终截图；
- 五个演示初始封面；
- 五段无声 WebM，再用本地 FFmpeg 转为 H.264 MP4；
- 视频总长 8～12 秒，开头约 0.5 秒、结尾约 1.5 秒。

### PPT

- 严格沿用现有六页和每页源布局；
- 第 1 页替换主截图为新版中文总览；
- 第 2～6 页删除左右对比或单张旧截图，使用对应封面作为主视觉；
- 若当前 PowerPoint 输出链可可靠嵌入 MP4，则嵌入并设置进入页面自动播放一次、不循环；
- 若嵌入能力不可验证，则交付封面版 PPT，并在版式中明确保留视频替换区域，不使用 GIF 降级；
- 每页保留原标题、业务价值和样机边界说明；
- 最终逐页渲染并检查字体、图片裁剪、媒体位置、占位符和溢出。

## 8. 能力边界

所有页面和材料必须持续表明这是确定性 Mock 样机：

- 不声称已接入真实生产数据；
- 不声称已具备真实智能优化算法；
- 不声称已完成 PLC、ECS、TOS 或 AGV 实机控制；
- 不声称已达到生产级弱网冲突合并；
- 不声称已正式投产。

页面可使用“样机演示”“规则样例”“模拟状态”，但不遮挡主要业务演示。
