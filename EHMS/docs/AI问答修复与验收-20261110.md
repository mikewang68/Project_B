# AI问答修复与验收

发布标识：EHMS-ai-reliability-20261110-r1。

## 已定位的原因

1. DeepSeek目录显示未就绪；旧逻辑未调用模型，但对“你好”仍检索设备/告警并转储JSON，造成答非所问。不是DeepSeek模型返回这些内容。
2. 问答前端默认25秒先中止；模型适配器单次默认45秒，工具调用可多轮，服务端降级结果也可能来不及回到页面。
3. node6共享回程proxy_read_timeout为40秒，不能只把前端等待改长而不限制后端。

## 本次修改

- 闲聊/合成连通性短句不检索设备数据库；已就绪模型可正常对话，未就绪模型返回明确的本地帮助，不冒充AI。
- 本地业务兜底输出中文字段摘要和来源，不再转储原始JSON；无数据/无权限/检索失败分别说明。
- 模型和多轮工具分析共享30秒预算；HTTP调用使用剩余预算。前端AI专用55秒等待，不影响CRUD默认超时；10秒有等待反馈，不重复自动发起请求。
- 模型输出上限768 tokens，提示优先3—5项、通常350字以内；如返回length截断则明确降级，不把残缺维修建议当完整回答。
- 未就绪原因、真实模型、本地检索/本地帮助分开显示；连接测试成功只代表短问答，不宣称所有业务分析通过。
- 不补造DeepSeek Key、不擅自开启外发、不自动把千问失败转发到DeepSeek。DeepSeek未就绪需按现有状态确认enabled/Key/dataPolicy；只有管理员在受保护配置中完善后才可真实调用。

## 发布保护

不是整包覆盖。发布器核对线上JAR及静态文件SHA256，只有3个AI源码家族的class被替换；所有其他class、依赖、IAM、审计、模拟任务代码和现有静态资源逐项保留；index只改AI脚本缓存版本。

不执行DDL、不重置账号、角色、密码或现有env；不更改共享网关/防火墙/SELinux策略。只短暂重启EHMS，验证health/匿名401/静态文件hash，失败回退代码和静态alias。后台模拟器沿用当前持久化配置，重启期间不声称零中断。

--check不发布；--apply须管理员sudo。上传到公共/home/bpoc-data/projects/Project_B/releases下不等于已经生效，必须看到AI_HOTFIX_DEPLOYED回执。生产业务账号问答仍须原有IAM会话验收，不能用匿名绕过或服务账号直调冒充。

## 验收

1. 原账号登录，千问发送“你好”/“请只回答：连接成功”：出现模型回答，无无关设备记录。
2. 选择一台模拟设备，问“列3项现场检查重点”；回答标模型/来源，超时则30秒预算后有明确降级而非25秒前端中止。
3. 问校准/工单：与来源页核对；无记录如实提示，不能编造日期、寿命、工单数量。
4. DeepSeek若仍未就绪，“你好”为本地帮助，业务查询为可读摘要；不能作为DeepSeek真实推理通过。
5. 切模型开新会话、不转发旧历史；跨用户/范围不可读取；草稿仍需权限与人工确认。
6. 后台动态提交、图表、日志照常；链上状态按真实TRUST回执，不由本次AI改造推断。
