# EHMS维修功能与需求工作簿验收清单

版本：EHMS-maintenance-ux-20261117-r2；负责人：闫鑫钰。

## 1. 这次为什么出错，改了什么

工单截图的 Write requires one authorized tuple 是服务端拒绝全局/多区域写操作，不是数据已丢失。此前发布遗漏了 AccountController 的作用域投影，导致前端只显示“区域待确认”，旧兼容逻辑直到提交才展示错误。本次增量补上 /auth/me 的可信 dataScope（mode/active/allowed/writeAllowed/writeBlockReason），不修改 IAM，不替用户选择区域、不新增权限。工单列表明确显示可写区域；不确定、全局、多区域或只读时禁用变更，并给出门户操作路径。最终权限仍由服务端核验。

AI 展开宽度大于收起偏移量，因此关闭后残留一条面板。本次关闭同步 hidden/inert/aria-hidden，防止视觉残留和隐藏输入继续获焦；重新打开恢复交互。

工单页从超长看板改为20张/页的筛选表格，每行都有“维修 / 复测 / 履历”和阶段对应动作；流转需填实际依据。维修档案显示当前下一步、实际执行数、本轮必测通过数及状态门槛。修正 contextDrawer 打开时的前端轮询暂停，避免填写中被刷新打断。每页增加“工作簿验收”，按R-E01～R-E08展开九问、操作入口与失败条件，标注待验证，不自动宣称需求已签收。

本次不是重做所有功能。上一版已落地可信业务签名、维护依据与去重提醒、量化维修、证据固化与修订、健康审核转单、逐设备摘要等后端流程；本次主要解决作用域诊断、维修入口和展示/关闭交互。

## 2. 先选择一个能写入的区域

1. 在统一门户的“当前范围”选择一个完整的 PROJECT_B / 已授权区域 / EHMS，点“应用范围”。例如 EHMS_DEMO 仅在账号确已授权时可选。
2. 回到 EHMS 工单页，点击“刷新操作范围”，应显示“当前可写区域：区域编号”。必要时重新登录已有会话。
3. 仅选项目、全局、多区域、只读账号不应能审批。换区域设备/工单数量减少是筛选结果，不是删除数据。不要为看到数据改查其他区域。
4. 单一区域仍提示动作未授权：需 IAM 菜单动作和 EHMS 原生动作均允许；系统不会将普通用户强改为管理员。
5. 若目标区没有设备/测点，先处理该区域的数据接入或正式迁移，不能把 UNASSIGNED 历史记录无条件拼进来。

## 3. 一张维修工单怎么验收（R-E05）

仅在隔离演示区域操作虚拟设备，标题使用“验收-日期-设备编号”，不要关闭既有未核对工单。

|步骤|操作人及输入|页面动作|通过证据|
|---|---|---|---|
|1 建单|有创建权限者，选当前区设备、主题、责任班组、计划窗口、实际原因|工单中心→新建工单|刷新后存在一张待审批单，设备编码正确|
|2 审批|有审批权限者，填写审批依据|该行→审批通过|变为待执行；可信操作者及流转原因可回查|
|3 开始|维修人员，填写开始依据|该行→开始维修|变为执行中，不自动触发PLC动作|
|4 必测计划|按该设备实际配置选1至100个启用测点|维修 / 复测 / 履历→必测计划|保存后回查计划仍在；不接受其他设备或归档测点|
|5 执行|实际动作、结果、安全措施、备件及数量；未用明确填写|同档案→登记维修执行|刷新可回查真实登录记录人、时间及全部输入；不预填虚构结果|
|6 提交复测|维修人员填写流转依据|回工单列表→提交复测|变为待复测；未执行时不应能完成闭环|
|7 量化复测|复测人员逐个填前后有限数值、登记单位、实际判据和通过/不通过|同档案→录入复测|每条有测点、值、单位、判据、时间和可信人员|
|8 复核|授权复核人，填结论、恢复决定、理由/限制|所有必测项本轮最新结果通过后→复核与关闭|变为已关闭，恢复AVAILABLE/RESTRICTED/NOT_RESTORED单独保存；刷新可回看|

告警来源工单进入原关联告警闭环档案，不建立第二份通用维修记录。不同人员必须由不同账号复核是否强制，仍待甲方制度确认，不把同账号测试说成职责分离验收通过。工单关闭只记录业务决定，不等于设备可启动许可。

必须验失败路径：全局/只读写入被拒；缺少实际流转原因被拒；漏测一项不能关闭；同一点最新失败不能用旧通过覆盖；返修前旧轮次结果不能代替新复测；其他设备测点/错误单位/非有限数值拒绝；不得用通用状态接口直接CLOSED；失败保留输入，修正后重试。

## 4. 工作簿逐项检查表（不等于自动验收通过）

|需求及功能|页面与最小实际操作|成功应看到什么|至少一项反向验证|
|---|---|---|---|
|R-E01 / F-E01|设备档案、部件BOM、测点：按统一编码查同一设备资料|部件、点位、单位、资料版本与来源对应同设备|无资料明确缺项，不换成相似设备|
|R-E02 / F-E08、F-E02、F-E19|实时监测：选测点和起止时间；公共MQ样本查事件与原始观测|曲线、明细、CSV对应；有源/接收时间、质量与模拟标志|BAD/STALE/缺值断开正常线，不补0；错误窗口被拒，超过上限提示|
|R-E03 / F-E22、F-E03、F-E20|告警中心筛选类型/等级，确认、分派、处置、关闭并回看履历|触发依据、实际原因、可信人员、状态与时间可追溯|空关闭原因拒绝；未闭环维修档案不能旁路关闭；质量异常不等于物理故障|
|R-E04 / F-E04、F-E21|设备维护依据→维护计划核算两次→点检→合格点检关联回填周期|同一周期只一条提醒；责任班组、条款覆盖说明、完成日期/读数保存|无依据/读数不猜到期；旧周期、错设备、不合格点检不能完成|
|R-E05 / F-E05、F-E14、F-E15、F-E13|按上一节完整跑一张维修工单|执行、安全、备件、量化复测、判据、签核与恢复限制刷新后可回看|漏测、失败、错误单位或跨设备记录不得关单|
|R-E06 / F-E10、F-E02、F-E11、F-E12、F-E13|告警证据：同设备历史窗口固化→人工诊断→追加修订|证据ID、SHA256、时间/质量/来源、前后结论及修订原因都在|无样本不补造；错设备/错误前序引用拒绝；不覆盖原结论|
|R-E07 / F-E02、F-E16、F-E17、F-E18|健康页：读质量→规则评估→人工审核接受→重复转单|因子/阈值/版本/有效期可解释；审核意见保留；重复转单还是同一工单|无阈值不评分；过期/回放不可作为当前维修决策；拒绝审核不能转单|
|R-E08 / F-E09（DTS协作F-D03/F-D05）|同设备GET /api/ehm/v1/devices/{code}/health-summary，对照DTS|设备、区域、assessmentId、有效期与EHMS相同|无评估UNKNOWN、过期STALE，分数为空而非0；跨区不能串读|

每条验收建议记录：需求编号、区域、设备/工单/告警ID、操作者岗位、操作时间、输入、预期、实际结果、刷新后的查询证据、通过/失败/待外部确认。上述是用例，不是已替你在生产数据库造数据并签收。

## 5. 未被这次补丁自动“完成”的内容

厂家正式BOM/阈值/周期/复测工况及验收标准、岗位分工与强制不同人复核、现场恢复许可、真实寿命预测模型、DTS两端签收、公共AUDIT新事件链上确认，都不能凭页面存在就判定完成。可选演示维护提醒定时器仍默认关闭；原有“动起来”模拟任务和公共MQ消费配置不动。

## 6. 回归与发布边界

服务器维护源码为唯一开发基线；本地只运行该服务器源码的只读测试快照，不维护另一套业务改动。后端288项、前端156项回归通过（零失败/错误/跳过）；浏览器使用真实HTML/JS和合成HTTP测试端，不冒充生产openGauss/IAM实业务验收。新包仅增量更新AccountController类族和8个页面资源；其余JAR条目逐字节保留、其余公开资源哈希保留。账号、IAM、数据库结构/数据、AI密钥、MQ及模拟配置均不改。

正式切换需执行本包发布脚本；通过健康、匿名拒绝及资源校验后才切入口，失败回退应用，不回滚或清空业务库。登录后的实际区域和业务流程仍需验收。
