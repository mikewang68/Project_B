# 设备健康管理系统（EHM）总体架构基线 v1.0

> 状态：建议冻结
>
> 适用阶段：Demo 完善、实验室联调、试点建设、后续生产化演进
>
> 本文只确定系统边界和技术结构，不替代尚待甲方确认的设备点表、协议参数、部署资源与验收指标。

## 1. 架构结论

当前 Demo 可继续作为页面样式、业务流程和接口联调样机，但不应继续在单个前端脚本和 Controller 直连 MongoDB 的结构上堆叠功能。

建议采用以下总体路线：

1. 后端以“模块化单体”起步，按业务域划分模块，模块间只通过应用接口或领域事件协作。
2. 模块内部采用端口—适配器结构，将领域逻辑与 Spring、MongoDB、openGauss、openGemini、RocketMQ 等基础设施隔离。
3. 实验室环境先部署两个无状态 Java API 实例，通过 Easegress 统一入口和负载均衡，满足分布式运行验证。
4. 资产、工单、权限等事务数据进入 openGauss；遥测与趋势数据进入 openGemini；缓存和幂等状态进入 Kvrocks；异步事件进入 RocketMQ；原始波形、附件和模型文件通过对象存储端口管理，具体产品待定。
5. MongoDB 保留为本地 Demo 和可选文档型存储适配器，不作为生产系统唯一数据源。
6. 前端迁移为 Vue 3 + TypeScript + Vite，按业务模块拆分路由、页面、状态和接口客户端；现有静态页面保留为 UI 参考。
7. AI 能力作为可替换服务接入业务模块，不直接访问生产数据库，不绕过告警、工单、权限和审计流程。

该路线兼顾三点：现阶段可以较快完成可运行 Demo；数据库和服务器方案变化时主要替换适配器与部署配置；业务扩大后可将遥测接入、预测计算、报表任务等高负载能力独立拆成服务。

## 2. 必须先冻结的系统边界

### 2.1 EHM 的职责

EHM 负责：

- 设备资产、部件/BOM、测点、传感器和故障模式管理；
- 设备运行数据的只读接入、校验、质量评价和状态展示；
- 阈值告警、复合规则、诊断证据、健康评分、趋势预测和寿命预测；
- 人工确认、点检、维护计划、工单执行、复测关闭和统计审计；
- 向统一数据底座、数字孪生、生产调度和安全卡控系统发布状态、告警和风险建议；
- 为管理人员、运维人员、专家和外部系统提供受控查询接口。

### 2.2 明确不承担的职责

- 不直接写 PLC，不直接启停设备，不下发安全联锁指令；
- 不替代既有安全控制系统、PLC、SCADA 或设备保护装置；
- 不以 AI 输出自动替代检修审批、作业许可和安全确认；
- 不在前端或浏览器中保存数据库密码、AI 密钥和设备侧凭据。

### 2.3 需求文字冲突的处理原则

需求材料中“远程控制”“本地控制”“发送联锁信号”“互为备份”等表述，与后续章节中的只读接入和不得直接控制 PLC 存在冲突。架构基线采用风险更低、边界更清晰的后续约束：

> EHM 只读采集设备信息，生成诊断、建议和非安全风险事件；安全控制和联锁仍由安全卡控系统及现场控制系统执行。

在甲方书面确认前，不实现任何 PLC 写入或设备控制接口。

## 3. 当前 Demo 审查结论

### 3.1 可以保留的部分

- 现有亮色工业界面可作为 UI 风格和演示素材；
- 已形成设备、告警、工单、趋势和 AI 场景的基本展示入口；
- 本地 Docker Compose 可继续作为单机演示环境；
- MongoDB 中的演示数据可作为测试夹具迁移，不必废弃。

### 3.2 不适合继续扩建的部分

| 问题 | 当前影响 | 调整方向 |
|---|---|---|
| 前端菜单、数据、渲染、接口和弹窗集中在单个 `app.js` | 修改相互影响，部分菜单只能显示通用占位页 | 按模块迁移到 Vue 3，路由、页面、组件、Store、API 分离 |
| Controller 直接依赖 MongoRepository | API、业务规则和存储模型耦合，更换数据库需大改 | 建立 Application Service、Repository Port 和数据库 Adapter |
| Device 同时承载资产、遥测快照、健康评分、数据质量和 RUL | 字段不断膨胀，历史版本和算法结果无法治理 | 拆成资产、测点、快照、评估、预测等独立模型 |
| 工单号由 JVM 内计数器生成 | 双实例或重启时可能重复 | 使用 UUID/雪花 ID 或数据库序列，业务编号由持久化规则生成 |
| 工单状态可接受任意字符串 | 无法保证流程合法，无法追责 | 建立状态机、操作权限、版本号和状态变更历史 |
| 驾驶舱使用 `findAll()` 后在内存聚合 | 数据增长后响应时间和内存不可控 | 分页、条件查询、数据库聚合、索引和预聚合 |
| 配置声明 RBAC 已强制，但后端尚无认证授权 | 配置与实际能力不一致 | 未实现前标记为关闭；实现 Spring Security 后再启用 |
| CORS 全开放、Mongo 端口暴露、默认弱口令 | 只适合本机演示 | 按 local/lab/prod Profile 分离配置，服务端管理密钥 |
| 演示数据初始化没有 demo 环境限制 | 联调或生产可能误写演示数据 | 初始化器只在 `demo` Profile 激活 |
| 缺少自动化测试 | 重构和多人集成风险高 | 增加状态机、应用服务、适配器、接口契约和架构边界测试 |

## 4. 目标逻辑架构

```text
浏览器 / 大屏 / 第三方系统
              │
     Easegress / Nginx
  认证、路由、限流、Trace ID
              │
┌─────────────┴─────────────────────────────────┐
│                 EHM API 应用                  │
│                                               │
│  资产台账   状态监测   告警诊断   健康预测    │
│  维护工单   分析报表   系统集成   平台治理    │
│                                               │
│     应用接口 + 领域事件 + 统一权限/审计       │
└───────┬──────────┬──────────┬──────────┬──────┘
        │          │          │          │
   openGauss   openGemini  RocketMQ   Kvrocks
   事务数据     时序数据     事件流      缓存
        │
  对象存储端口：波形、附件、模型、报告
        │
  边缘网关/统一数据底座/孪生/调度/安全卡控
```

### 4.1 分布式与可拆卸的含义

- **无状态 API**：登录会话、幂等键、短时状态不保存在单个 JVM 内，使 node4/node5 可同时运行。
- **可替换存储**：业务层只依赖 Repository Port，不依赖 MongoRepository、JPA 或数据库 SQL。
- **可替换消息系统**：业务层发布领域事件，由 RocketMQ Adapter 或本地事件 Adapter 承担发送。
- **可替换 AI**：业务模块调用统一的预测/问答端口，模型可由规则、Python 服务、远程 API 或后续本地模型实现。
- **可拆分服务**：模块先同进程运行；达到独立扩容、资源隔离或团队边界条件后，再拆出进程。

## 5. 业务模块划分

### 5.1 asset：设备资产与 AI 台账

负责设备、位置、设备类型、部件/BOM、测点、传感器、技术参数、图纸、文档、责任班组、故障模式和履历。

AI 台账在本模块提供“资料抽取、字段建议、缺项检查、重复资产识别和自然语言检索”，但所有自动生成内容必须标明来源、置信度和人工确认状态。

### 5.2 monitoring：状态监测与数据质量

负责当前状态快照、实时指标、历史趋势、测点质量、断流、漂移、越界、时间同步、数据新鲜度和健康评估就绪度。

本模块不保存全部原始高频波形到事务库；原始波形进入对象存储，特征和索引进入时序库。

### 5.3 alarm-diagnosis：告警与诊断

负责阈值、组合规则、抑制、去重、告警生命周期、证据包、故障树/FMECA、诊断结论、人工确认、知识库和相似案例。

告警状态建议冻结为：`NEW → ACKNOWLEDGED → INVESTIGATING → RESOLVED → CLOSED`，另设 `SUPPRESSED` 和 `INVALID` 分支；每次迁移记录操作者、时间、原因和版本。

### 5.4 health-prediction：健康评估与预测

负责健康指数、部件评分、基线、劣化趋势、异常检测、剩余寿命 RUL、预测任务、模型版本、特征版本、评估结果和模型监测。

预测结果是带有效期的不可变记录，不直接覆盖资产字段。每条结果至少记录模型版本、输入时间窗、数据质量、输出值、置信区间、生成时间和适用范围。

### 5.5 maintenance：点检、维护与工单闭环

负责维护策略、计划、点检任务、缺陷、工单、人员、备件需求、作业记录、复测、验收和关闭。

工单状态建议冻结为：`DRAFT → SUBMITTED → APPROVED → ASSIGNED → IN_PROGRESS → WAITING_VERIFY → CLOSED`，并允许按权限进入 `REJECTED`、`CANCELLED` 或 `ON_HOLD`。禁止直接从任意状态跳到关闭。

### 5.6 analytics-report：可靠性与分析报表

负责设备健康分布、告警统计、MTBF、MTTR、可用率、OEE 相关指标、维护执行率、预测命中率、数据质量和报表任务。

OEE 是否适用于全部六类设备应由甲方确认；不具备明确计划产量、实际产量和质量产量的设备，不强行计算 OEE，可改用可用率、故障率、停机时长等指标。

### 5.7 integration：外部系统集成

负责统一数据底座、数字孪生、生产调度、安全卡控、能源系统、现场设备/边缘网关的适配器和接口映射。

外部接口模型不得直接成为内部领域模型。每个外部系统使用独立 Anti-Corruption Layer 完成字段、枚举、时间、单位和设备编码映射。

### 5.8 platform：平台公共能力

负责身份认证、RBAC、组织与数据权限、配置、字典、审计、通知、附件、任务调度、幂等、统一异常、操作日志和可观测性。

平台模块提供能力，不反向依赖具体业务模块。

## 6. 模块内部结构

每个业务模块使用同一结构：

```text
module-name/
├─ domain/          实体、值对象、领域服务、领域事件、业务规则
├─ application/     用例、命令、查询、事务边界、DTO 映射
├─ ports/           Repository、消息、文件、AI、外部系统接口
├─ adapter-in/      REST、消息订阅、定时任务
└─ adapter-out/     openGauss、Mongo、openGemini、RocketMQ、外部 API
```

强制依赖方向：

```text
adapter-in → application → domain
adapter-out ───────实现────→ ports ← application/domain
```

`domain` 禁止依赖 Spring Data、MongoDB、JPA、HTTP 客户端和前端 DTO。跨模块不得直接访问对方数据库表或 Repository。

## 7. 核心数据模型拆分

| 数据对象 | 作用 | 建议存储 |
|---|---|---|
| Asset、Component、BOM、MeasurementPoint、Sensor | 资产和测点主数据 | openGauss；本地 Demo 可使用 Mongo Adapter |
| TelemetrySample、FeatureSeries | 慢/中速遥测与特征序列 | openGemini |
| RawWaveform、Attachment、ModelArtifact | 原始波形、附件、模型文件 | 对象存储端口 |
| CurrentStateSnapshot | 页面所需的最新状态投影 | Kvrocks + 可重建持久化投影 |
| DataQualityAssessment | 缺失、延迟、漂移、越界和就绪度 | openGemini/openGauss |
| Alarm、EvidencePackage、Diagnosis | 告警闭环和诊断证据 | openGauss |
| HealthAssessment、PredictionResult | 健康评分、异常和 RUL 结果 | openGauss + openGemini 趋势 |
| MaintenancePlan、Inspection、WorkOrder | 维护与工单事务 | openGauss |
| AuditEvent | 操作和关键数据变更审计 | openGauss；归档到对象存储 |

所有业务对象使用全局唯一 ID，并保存统一设备编码、场站编码、来源系统、数据版本和时间戳。时间统一使用带时区的 ISO 8601 表达，内部按 UTC 保存，界面按场站时区显示。

## 8. 接口与事件基线

### 8.1 REST API

- 基础路径：`/api/ehm/v1`
- 写操作支持 `Idempotency-Key`
- 更新操作使用版本号或 `If-Match` 实现乐观锁
- 列表接口统一分页、排序、筛选格式，禁止默认返回全部记录
- 错误响应统一包含：`code`、`message`、`details`、`traceId`、`timestamp`
- 接口契约由 OpenAPI 维护，前端客户端从契约生成

### 8.2 事件信封

```json
{
  "eventId": "uuid",
  "eventType": "ehm.alarm.created.v1",
  "occurredAt": "2026-09-05T10:00:00+08:00",
  "producer": "ehm",
  "siteId": "SITE-001",
  "assetId": "ASSET-001",
  "traceId": "uuid",
  "schemaVersion": 1,
  "payload": {}
}
```

消息消费必须支持幂等、失败重试、死信记录和人工补偿。事务数据与事件发送使用 Outbox 模式，避免数据库提交成功但消息发送失败。

### 8.3 建议主题

- `ehm.telemetry.feature.v1`
- `ehm.data-quality.changed.v1`
- `ehm.alarm.lifecycle.v1`
- `ehm.health.assessed.v1`
- `ehm.prediction.generated.v1`
- `ehm.work-order.lifecycle.v1`
- `ehm.integration.risk-advisory.v1`

主题名称最终应与六个系统的统一命名规范共同冻结。

## 9. AI 能力接入框架

### 9.1 AI 与业务功能的结合

| AI 能力 | 所属业务模块 | 输入 | 输出 | 必须保留的人工环节 |
|---|---|---|---|---|
| AI 台账 | asset | 铭牌、文档、历史台账 | 字段建议、缺项、关联部件 | 台账管理员确认后入主数据 |
| 异常检测 | health-prediction | 特征序列、工况、基线 | 异常分数、时间窗、影响测点 | 专业人员确认告警或忽略 |
| 故障诊断助手 | alarm-diagnosis | 告警、证据包、FMECA、案例 | 原因排序、检查建议 | 运维人员形成正式诊断 |
| RUL 预测 | health-prediction | 劣化特征、工况、维修史 | 剩余寿命区间和置信度 | 维护人员决定计划 |
| 智能问答 | 多模块只读查询 | 权限内台账、告警、工单和知识库 | 带来源的回答和跳转入口 | 不自动执行控制和审批 |

### 9.2 统一 AI Port

业务模块只调用 `PredictionPort`、`DocumentExtractionPort`、`AssistantPort` 等接口。具体实现可以是：

- 规则/统计模型，适用于早期无训练数据阶段；
- 独立 Python 推理服务；
- 已授权的远程大模型 API；
- 后续本地 GPU 推理服务。

API 地址和密钥只由后端环境变量或密钥管理设施读取。前端不得直接调用外部 AI API。

## 10. 三套部署形态

### 10.1 local：开发者单机

- Nginx/前端 + Java API + MongoDB；
- Docker Compose 一键启动；
- 使用 `demo` Profile 和演示数据；
- 仅用于开发、演示和接口试验。

### 10.2 lab：实验室三节点联调

| 节点 | 建议部署 |
|---|---|
| node6 | Nginx 静态前端、openGemini、Nightingale、Categraf |
| node4 | EHM API 实例 A、openGauss、Kvrocks、Easegress |
| node5 | EHM API 实例 B、RocketMQ、Easegress Worker |

两个 API 实例使用相同构建产物，仅配置不同实例 ID。数据库、中间件和外部接口地址由环境变量/Profile 注入，镜像内不固化 IP、口令和环境差异。

### 10.3 prod：最终生产环境

- 独立数据库高可用和备份；
- TLS、最小权限、网络分区、密钥管理和审计归档；
- API 多实例、健康检查、滚动升级和限流熔断；
- 对象存储、备份与灾备产品按采购结果接入；
- 信创软硬件适配在产品型号确定后通过 Adapter 和镜像重建完成。

## 11. 配置管理基线

配置分为三类：

1. **普通运行参数**：Profile、端口、超时、分页、功能开关，可进入版本库中的模板。
2. **环境连接参数**：数据库、消息系统、外部服务地址，由环境变量或部署平台注入。
3. **秘密信息**：口令、Token、AI Key、证书私钥，禁止进入 Git、前端包和普通配置文件。

现有 `.config.json` 应只作为统一配置模板或启动时导入源，并由后端映射为类型化配置；不能与 `application.yml`、Compose 环境变量各自维护一套互相冲突的值。配置中标记为启用的能力必须已经实现，否则应保持关闭并给出状态说明。

建议 Profile：

- `demo`：本地 Mongo、演示数据、宽松调试日志；
- `lab`：三节点外部中间件、双实例、实验室账号体系；
- `prod`：正式认证、TLS、审计、备份、高可用和最小权限。

## 12. 非功能指标落地

| 指标 | 架构措施 | 验证方式 |
|---|---|---|
| ≥50 并发用户 | 双 API 实例、连接池、缓存、分页 | k6/JMeter 场景压测 |
| ≥200 台设备 | 设备编码治理、批量接入、按场站/设备分区 | 200 台模拟设备联调 |
| ≥100 万点/分钟 | 边缘聚合、批量写入、RocketMQ、openGemini | 持续写入压测，观察丢点和延迟 |
| 页面 ≤3 秒 | 聚合 API、缓存、前端懒加载 | P95 页面和接口监控 |
| 7 天查询 ≤2 秒、1 年查询 ≤5 秒 | 时序分区、降采样、预聚合、查询限界 | 固定数据集基准测试 |
| 可用率 ≥99.9% | 无状态双实例、健康检查、故障转移 | 单实例故障演练 |
| RTO ≤30 分钟、RPO ≤5 分钟 | 数据库备份/WAL、恢复手册、定期演练 | 恢复演练记录 |
| 单模块故障不影响其他模块 | 模块边界、超时、隔离、异步事件 | 故障注入和降级测试 |

“百万点/分钟”不能直接进入普通 REST API 或事务库。设备侧应在边缘完成协议适配、时间对齐、质量标记和必要特征提取，再批量进入消息/时序链路。

## 13. 何时从模块化单体拆成独立服务

出现下列任一条件时再拆分：

- 某模块需要独立扩容或独占 GPU/高 CPU；
- 遥测接入吞吐影响事务 API；
- 预测或报表任务需要独立调度和资源配额；
- 发布频率、故障隔离或团队职责已形成明确边界；
- 安全域要求模块运行在不同网络区域。

优先可拆出的能力顺序：遥测接入 → 预测推理 → 报表任务 → 文件/波形处理。资产、告警和工单在业务规则稳定前保留在同一事务边界中。

## 14. 下一阶段：架构基线重构

本阶段不新增大量页面，目标是把当前 Demo 变成可持续扩建的工程骨架。

### 14.1 本阶段完成判据

## 15. 架构重构后的首个业务闭环

首个可用版本优先实现 P0 闭环：

```text
资产/BOM/测点建模
        ↓
只读采集与数据质量判断
        ↓
告警生成与证据包
        ↓
人工确认/诊断
        ↓
生成并审批工单
        ↓
执行、复测、关闭
        ↓
可靠性统计与全程审计
```

这条链路跑通后，再扩展高级预测、AI 助手、跨系统协同和多场站能力，避免形成大量互不连通的展示页面。

## 16. 仍需甲方或项目组冻结的事项

1. EHM 只读边界及与安全卡控系统的责任划分；
2. 六类设备的准确数量、层级、统一编码和设备/BOM 模板；
3. 现场协议、点位、采样频率、时间同步、质量码和历史数据可用性；
4. D 类生产调度接口的详细字段、方向、频率、失败处理和责任方；
5. B 类安全卡控接口是否完全采用隔离区消息/API，是否删除 Modbus TCP 表述；
6. OEE、MTBF、MTTR、健康评分、RUL 的适用设备、口径和验收方法；
7. 用户组织、角色、数据范围、审批流程和审计保留期限；
8. 对象存储、统一身份认证、配置中心、证书和密钥管理产品；
9. 生产环境节点、网络分区、域名、TLS、备份与灾备方案；
10. AI 数据出域限制、模型部署位置、可解释性和人工确认责任。

在上述事项未冻结前，可使用 Adapter、功能开关和模拟数据推进开发，不应把临时参数硬编码进领域逻辑。
