# EHM 本地持续运行模拟器

版本：本地虚拟运行 v1，2026-10-30。本轮不提交 Git、不推送 GitHub、不部署服务器。

## 1. 做到了什么

不是向前端塞固定数字，也不是让数据库每天增加无关联的设备。已存在的虚拟设备持续产生测点采样，数据质量检查和规则健康评估读取这些采样；累计工时触发维保告警，再关联待办、工单、维修档案、库存流水和知识案例。

只覆盖当前已实现的业务链路，不表示全部67个需求菜单都已开发完成。真实设备协议、厂家寿命、经验证AI预测、生产OEE、短信/邮件和区块链联调不在本次本地模拟中冒充完成。

## 2. 打开与停止

本机入口：http://127.0.0.1:18294/?page=sample-workbench

在本机实际工作目录打开 PowerShell，执行（工作区便捷入口）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\启动EHM虚拟运行.ps1
```

账号：`simadmin`（超级管理员）与 `simviewer`（一般用户）。两者密码由本机首次启动随机生成，查看：

`Project_B-github-staging\EHMS\.local\simulation\accounts.private.json`

这是新的本地隔离库，不使用正式统一平台账号。不要把该私有文件发给他人或加入 Git。

停止时执行同一脚本并加 `-Stop`。停止不会删除数据库、工单或日志。代码变动后需要重新构建时加 `-Rebuild`；重新构建前先停止。

源代码内的通用启动脚本是 `EHMS/scripts/start-simulation-local.ps1`；其他电脑需要 Java17 和 Maven，支持 `-JavaHome`、`-Maven` 参数。首次 Maven 构建还需要已安装的公共 `AUDIT/sdk/java` 的 `audit-client:1.0.1` 依赖。

## 3. 页面怎么操作

左侧“集成与系统 → 演示数据与功能验收”顶部是“虚拟运行控制台”。

首次使用：初始化设备范围 → 组会加速模式 → 推进一轮。初始化仅在空的 SIM_ 项目创建数据，重复初始化不重置已有设备或业务流程，不与旧8台固定样例混装。

- **日常持续模式**：每300秒采样一次，每轮推进300/3600个模拟小时。不自动审批维修，留下任务供人工处理。
- **组会加速模式**：每5秒采样一次，每轮推进1个模拟小时，用“[虚拟]运行模拟器”推进审批、执行、待复测和闭环。
- **推进一轮**：暂停时手动推进，适合逐步讲解。
- **开始自动运行 / 暂停**：由后端调度，不依赖浏览器是否打开。
- **调整参数**：先暂停，可设置5～86400秒的间隔、每轮大于0且不超过24小时、周期、提醒比例和自动流程开关。虚拟测点采样周期同步调整，避免长间隔被误判断流。

页面每5秒检查新轮次，检测到新数据后刷新当前已实现页面。编辑输入框、打开弹窗或抽屉时暂缓刷新，避免冲掉尚未提交的内容。离开编辑区域后恢复。浏览器关闭后后台仍运行；电脑关机/睡眠期间不运行，不虚构那段时间的采样。服务重启保留运行/暂停状态，错过的轮次只补当前一轮，不集中补造历史。

加速模式在总轮次每到360的整数倍时自动暂停，需手动再次开始。总计8640轮触发容量保护，避免无人管理无限增长；默认持续模式约30天到达上限。原始虚拟时序每288轮清理真实入库时间超过7天的数据，不删除业务记录或审计。未做30天长跑或生产容量压测，长期运行需按磁盘和查询耗时观察、归档。

## 4. 最新清单覆盖口径

只读来源：`设备范围-v0.1-20260826.xlsx`，原文件未改动。

47条来源记录映射为29个去重监测范围项，每项创建1个虚拟实例、1个虚拟监测部件、3个虚拟测点，共29个实例、87个点。**29不是现场真实设备台数。** 数量、现场编码和厂家参数仍待确认。

范围包括：门式/桥式起重机、集装箱门吊、汽车衡、轨道衡、筒仓、翻箱机、拆箱房、除尘器、提升机、空气斜槽、风机、卸料设备、空压机、维修间、ECS、识别/道闸、UWB、皮带输送、密闭管道/流量计/气力输送、RFID、抓取引导，以及雷达、视频分析盒、摄像机、声光报警器、车载屏。

6个EHM单台模板仅关联已有范围，不重复建立设备。IF编号只是接口研究范围ID，不当作已确认的现场设备ID。电子设备只模拟自身温度、链路时延、丢包等健康状态，不执行视频AI、不操控道闸或声光器。

原行号→范围→虚拟设备映射及源文件SHA256保存在 `source/backend/src/main/resources/simulation/equipment-scope.json`。开发期重新解析可用 `scripts/import-simulation-catalog.py`，需要 openpyxl；运行服务不需要 Excel 或 Python。

## 5. 数据如何驱动功能

| 功能 | 触发与新增内容 | 验收入口 |
|---|---|---|
| 台账、BOM、测点、模板 | 初始化29设备/29部件/87点/4类草稿模板 | 资产中心 |
| 实时曲线 | 每轮87点，实际写入时间、带SYNTHETIC质量标记 | 实时监测 |
| 数据质量 | 每24轮的第12～14轮让ECS源时间过期；第15轮恢复 | 数据质量 |
| 规则健康评估 | 有效采样经既有规则评分；质量不足则不生成新分数 | 健康评估、劣化趋势 |
| 周期预警 | 默认40小时演示周期，累计到80%触发，每周期一套 | 告警中心 |
| 待办与工单 | 关联告警号、设备号、工单号，站内提醒 | 我的待办、工单中心 |
| 维修复测 | 加速模式逐轮审批→执行→待复测→闭环；前值来自告警时采样 | 维修记录与复测 |
| 备件 | 4类虚拟耗材包，期初各6套；执行时预留并领用，库存不足生成待办 | 备件需求建议 |
| 知识库 | 维修闭环新增待审核草稿，不伪造专家审核 | 故障知识库 |
| 点检 | 初始化及每跨24模拟小时新增各设备点检任务，留待人工执行 | 点检管理 |
| 班组交接 | 初始化及每跨12模拟小时，从已有未闭环告警/工单汇总草稿 | 班组交接 |
| 校准 | 初始化及每7模拟天新增明确虚拟的校准记录，无真实证书 | 传感器与计量校准 |
| 配置变更 | 首台设备初始化及每7模拟天新增采样频率评估草稿，不自动审批/下发 | 配置变更与数字履历 |
| FMECA | 4类明确假设的虚拟风险条目，评分不代表厂家结论 | FMECA |
| 驾驶舱/报表 | 读取业务数据库聚合，新建和关闭事件按真实日期统计 | 综合驾驶舱、KPI、日报 |
| 日志 | 真实HTTP操作日志+虚拟后台JOB操作，统一标识系统来源 | 操作日志 |

站内待办只是软件提醒；不代表真实人员已经收到或签收。耗材库存不足时不自动伪造采购，需用虚拟仓库 `SAMPLE-LIVE-WH` 手动补货。未实现的图表不会为了“每天变化”而填假结果。

累计总工时不因保养归零；本维保周期工时在闭环后归零。检修/离线期间不增加已确认运行工时。40小时仅是**演示维保周期**，不是设备设计寿命，也不是AI预测剩余寿命。

## 6. 组会建议演示顺序

1. 控制台展开设备范围，说明来源47行、去重29类，实际数量未确认。
2. 切换加速模式并推进一轮，查看87条新采样、曲线与规则评分。全新场景首台起始31.5周期小时，因此第一轮跨过32小时提醒阈值；已有验收场景保留历史，不保证每次再触发同一条告警。
3. 告警→待办→工单，按设备号或 `SAMPLE-LIVE-` 前缀查关联记录。
4. 再推进四轮，查看审批、执行、复测和关闭记录；耗材领用与待审核知识案例同步出现。
5. 查看日志中的 `ehm-simulator`、`sourceKind=JOB`，并区分登录管理员手动操作的HTTP日志。它们是本地持久化记录，**未发送公共AUDIT，也未上链**。
6. 自动运行到第12～14轮，查看ECS数据质量阻断；第15轮恢复后告警与核查待办闭环。阈值判定使用当前虚拟采样周期，半天采样也可演练。
7. 展示点检、交接、校准、配置草稿。暂停后可用一般用户登录验证只能查看、不能控制模拟器或进行增删改。
8. 结束后切回日常持续模式并开始运行。已有人工更改的工单状态与模拟器预期不一致时，自动流程不强行覆盖；需人工核查处理。

## 7. 数据库与安全边界

本地使用文件型H2和sample持久化时序，激活 `server,simulation-local` 两个 profile，复用服务器版的领域服务、JDBC仓储和HTTP接口。**不是恢复Mongo方案**；正式服务器原openGauss/openGemini配置没有更改。本地H2验证不能当成真实openGauss/openGemini联调或性能验收。

仅监听127.0.0.1:18294。私有数据目录 `.local/simulation` 已被Git忽略，采用本机用户权限。正式 profile 默认不启用模拟器，控制API保留登录、CSRF、管理员和项目范围校验。

启动脚本清除子进程继承的旧EHM环境变量并注入独立本地配置，避免误读服务器凭据。模拟服务启动时校验SIM_项目、sample时序、样例开关、外部AI关闭、公共日志投递地址为空，条件不符拒绝启动。

所有后台虚拟操作仍写本地持久化审计队列；公共AUDIT投递关闭，不能把队列PENDING当上链失败或成功。本轮不会改动其他人的服务、公共data目录、共享账号或服务器数据。

## 8. 自动验收

后端：`source/backend` 运行 `mvn test`。前端：EHM目录运行 `node --test tests/*.test.cjs`。

实际HTTP验收：

```powershell
python scripts/verify-simulation.py --accounts .local/simulation/accounts.private.json --output .local/simulation/acceptance-report.json --leave-running
```

只允许loopback，先核验SIM_项目，再检查权限、覆盖、幂等、断流恢复、各业务接口、后台定时与暂停。不会清库或改账号；会在模拟库产生演练记录，最后切回持续模式。自动报告不包含密码或令牌。

本轮实测结果另见 `docs/模拟持续运行验收结果.md`。现有业务仍有设计展示页，本次不是“全需求交付完成”的声明。
