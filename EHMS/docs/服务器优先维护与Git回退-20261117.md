## 本轮发布方式

不是整包替换：对当前实际运行JAR重新编译73个类，校验未修改的类、依赖、资源全部逐字节保留；只增量更新6个前端资源，保留原有统一认证、AI、自动刷新、MQ与模拟器入口。

不修改数据库结构、账号密码、IAM权限、AI密钥或模型策略、MQ组/偏移、模拟器配置；演示维护提醒扫描仍默认关闭。真实登录业务验收仍须发布后进行。

GitHub包含完整维护源码及测试；现网部署采用受控的类补丁而非全量重编替换。重建整个源码树不等价于此次增量二进制，不得跳过实际运行包差异核验而直接复制全量JAR。

## 后续流程

1. 在服务器确认服务JAR、Web别名和Git提交；先检查`git status`，保留其他人的未提交改动。
2. 在维护工作树创建任务分支或检查点，修改EHMS对应源码；不把账号、环境文件、运行库和私钥加入Git。
3. 对实际运行基线编译和测试。保留当前“动起来”、IAM、AI、日志和公共数据接入，不用旧源码整包覆盖。
4. 产生独立的新发布目录和摘要；先预检再切换，失败恢复原JAR和Web别名。
5. 发布成功再核对网站、服务、提交哈希与回执，完成真实登录验收；Git推送只更新EHMS范围。

## 回退边界

- 尚未提交的修改，不直接执行`git reset --hard`；先保存差异并核实归属。
- 已提交的代码，通常使用`git revert <提交>`产生可追踪回退提交，再测试、构建和重新发布。
- **Git只回退源码，不会自动回退正在运行的JAR、Nginx别名、数据库、账号、环境文件或消息偏移。**
- 本轮发布器启动/资源核验失败时只移除自己新增的服务覆盖配置、恢复原Web别名并重启原后端，不删除业务数据或账号。成功发布后，如需回退运行版本，先核实其私有回执记录的旧路径和本轮覆盖配置；不能删掉其他版本覆盖文件。
- 增量功能新增的业务记录保留，不把“回退应用”等同于删除已发生的维修、复测和审计事实。

服务器凭据只在SSH/sudo或既有凭据管理器中使用，不写入公共工作树。普通账号可维护自己的公共目录源码；切换受保护的systemd服务仍须管理员授权，不绕过sudo。
