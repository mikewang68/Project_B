# AI双模型切换与验收（2026-11-05）

## 本次实现

基于当前IAM V2.1功能恢复工作树增量增加，不回退账号、菜单、数据范围、日志或持续模拟功能。没有修改设备数据、后台模拟器周期和累计进度。

聊天框底部增加“对话模型”选择器：

- `lab-qwen`：实验室千问，已通过实验室`/v1/models`核对模型ID为`Qwen3.8-27B`。
- `deepseek`：DeepSeek，保留旧`ehm.ai.*`配置兼容，也可单独设置`ehm.ai.deepseek.*`。

模型选择属于当前浏览器标签页/当前对话，不会修改其他用户的全局模型。切换时开启新对话，旧对话历史不会自动发送给另一模型。回答标明供应商、模型、检索来源和实际使用的模式；模型失败只回退本地数据库检索，不自动向另一供应商发送数据。

实验室千问默认关闭工具调用：系统先按原有权限读取并脱敏业务记录，再交给千问分析。可查设备、告警、工单、待办、交接、校准、变更、模板和知识案例。AI无业务写权限；转待办/交接仍需人工确认及对应ADD权限。

## 配置与密钥

参考`config/ehm-ai.multi.env.example`，在后端的私有环境文件中加载，并将示例域名替换为获批的实际实验室地址。它是附加配置，不能覆盖原数据库、IAM或整个服务器环境文件。实际实验室地址仅在本机私有配置中填写，不嵌入公开源码。

- 新配置前缀：`EHM_AI_LAB_*`和`EHM_AI_DEEPSEEK_*`。
- 默认选择：`EHM_AI_DEFAULT_MODEL=lab-qwen`或`deepseek`。
- 每个配置独立指定`API_KEY_FILE`。密钥文件由服务账号读取，Linux权限600；不能放进公开web目录。
- HTTP实验室接口仅允许后端配置的精确受信任地址（含端口）。不允许前端提交任意模型URL或密钥。当前HTTP地址应仅通过实验室可信网络/VPN访问。
- 返回给浏览器的模型目录只包含稳定ID、显示名称、模型名及配置状态，不包含密钥、密钥文件路径或供应商地址。
- 原`ehm.ai.*`指向DeepSeek时，未提供独立DeepSeek配置就继续用原配置。原配置已改为实验室模型时，旧DeepSeek密钥需要通过独立配置重新关联；不会将千问的密钥当作DeepSeek密钥。缺少密钥时保留选项并显示未就绪，不能声称DeepSeek已连通。

本机已将用户提供的实验室Key保存至被Git忽略的`.local/ai/lab-api.key`，文件ACL限当前Windows用户读取/写入。私有附加配置为`.local/ai/multi-model.properties`。启动本机后端时，可在原有启动配置后附加：

```text
--spring.config.additional-location=optional:file:./.local/ai/multi-model.properties
```

该相对路径假设工作目录为EHMS；不改变原有账号或数据库配置。私有文件不会打入交付包，因此复制源码或ZIP并不等于已把密钥部署至服务器。服务器需单独配置两个受保护密钥文件。

## 接口契约

所有接口仍在原登录认证、菜单和原生权限守卫下。需要`EHMS:ai-assistant`的`VIEW`及原生权限`ehealth:wb:assistant:view`；POST/DELETE沿用CSRF要求。

| 接口 | 说明 |
| --- | --- |
| `GET /api/ehm/v1/assistant/models` | 返回`models[{id,label,status}]`及`defaultModelId` |
| `GET /api/ehm/v1/assistant/status?modelId=lab-qwen` | 查询所选模型配置状态；ready不代表网络验证通过 |
| `POST /api/ehm/v1/assistant/test?modelId=lab-qwen` | 不含业务记录的最小连接测试 |
| `POST /api/ehm/v1/assistant/chat` | 原有JSON新增可选`modelId`；如`{"message":"查询告警","modelId":"lab-qwen","sessionId":null,"deviceCode":null}` |

`modelId`只接受后端白名单中的ID。未知ID返回400；已有对话改用另一模型返回409，必须新开对话。省略ID时，新对话选后端默认模型，已有对话沿用最初模型。会话仍按用户、登录会话、项目、区域和授权版本隔离。

## 用户验收

1. 登录原账号，进入“AI设备助手”，打开对话。
2. 底部选择“实验室千问 · Qwen3.8-27B”，点“测试连接”。
3. 问“当前有哪些设备需要关注？请给检查建议”，核对回答的模型、来源及数据范围。
4. 切换DeepSeek，应出现新对话提示；不会延续刚才的聊天记录。有有效配置时可测试，否则明确显示配置缺失和本地检索。
5. 切回千问，连续追问；只有选中的模型被调用。后台仍按原持久化设置生成虚拟数据，关闭网页不会停止原任务。
