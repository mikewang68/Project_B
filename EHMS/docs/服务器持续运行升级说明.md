# 1.9.0 共享服务器持续运行升级

本轮范围：保留虚拟运行新增能力，将其部署到已有EHM服务，继续使用服务器统一IAM账号，不替换为本机simadmin/simviewer。不得上传本机账号文件、H2、真实环境变量或模型密钥。

## 两种明确不同的运行方式

- `isolated`：原本机验收方式，SIM_项目、H2/sample时序、外部模型与公共日志投递关闭。
- `shared-synthetic`：显式批准后运行在已有授权项目。业务仍存原openGauss；只有SAMPLE-LIVE-虚拟测点样本进入独立类型sample-telemetry，带SYNTHETIC质量码。真实测点仍使用原openGemini，故障时不会回退到模拟库。

共享模式启动需要同时满足：simulation.enabled=true、shared-data-approved=true、原openGauss/openGemini适配、模拟项目与后台默认项目一致且不是UNASSIGNED。原IAM项目授权不增加；只能在已获管理员授权的项目安装。

初始化只增加带虚拟标识的新数据。若未初始化但已有相同虚拟设备编码，则拒绝覆盖。重启不重复初始化，不覆盖保存的暂停状态。普通用户不能启动、调参或安装；已有驾驶舱查看权限可读取本项目模拟状态。

默认每300秒采样一轮、自动维修关闭，先由用户手动验收。控制台可暂停并切换每5秒/1模拟小时的加速模式。真实设备仍不被控制，40小时仅为演示维保周期。共享模式不会自动删除历史样本；8640轮达到容量保护后需人工归档和安排下一阶段。

服务器日志策略保持原样。虚拟JOB操作明确记录SYSTEM操作者和[虚拟运行]摘要；是否送达公共AUDIT、是否上链依现有配置与真实回执判断，不能因模拟器启动就声称上链。

## 产物准备

先正常构建服务器JAR，不激活simulation-local Maven profile：

```text
mvn -f source/backend/pom.xml -DskipTests package
python scripts/prepare-simulation-release.py --output <新的发布目录>
```

脚本拒绝包含H2的服务器JAR，源码清单使用Git排除规则，不含.local、target、密钥、实际ehm-server.env或账号文件。产物包含源码、web、JAR、SHA256清单及定向升级工具。

## 已有服务定向升级

发布目录放在共享 `/data/projects/Project_B/releases/`，不要放个人家目录。

`scripts/deployment/install-running-server.py` 是针对现有统一EHM systemd服务及`/ehm/`静态入口的工具，需要节点管理员执行。使用--expect-manifest核对事先审查的SHA256；可以先不加--apply只检查条件。

工具执行的保护步骤：

1. 从原运行进程读取环境和启动参数，使用原JAR的配置资源及Spring解析器核实仍为IAM模式；兼容SPRING_APPLICATION_JSON、JVM属性及配置文件，不仅检查EHM_AUTH_MODE。只启动不扫描业务组件、无自动配置的空解析上下文，不启动端口、数据库服务或任何EHM业务Bean。读取现有管理员项目映射，不创建、修改、重置任何账号。
2. 核对所有产物哈希，确认旧JAR仍可用于回退。
3. 只读连接原openGauss，备份当前项目全部业务聚合，计算已有本地账号行和认证文件摘要；私有备份权限700/600。
4. 仅新增本EHM单元的99-ehm-running-simulation.conf，保留原环境、Java命令与资源设置，附加模拟配置和新JAR路径。
5. 后端就绪、29类虚拟设备、87个新样本、定时轮次、已有业务行及账号摘要验证通过后，才更新唯一的`/ehm/`静态alias。
6. `nginx -t`通过才重载，其他系统位置、网关、IAM/SYS、SSO凭据与路由不更改。
7. 公共源码同步到既有共享EHM目录，私有配置不在源码包内，不覆盖。

出错则回退本次新增的EHM单元覆盖及原静态alias，重启旧EHM。不会为了回退代码而删除数据库记录；新增虚拟记录保留明确标识。错误详情仅写服务器private-deployment/last-error.private.log，公开输出不含凭据。

重启会使内存中的EHM会话失效，需要重新从统一入口登录，**不是密码被更改**。原用户名、密码、角色、项目权限均沿用。

部署工具r2修复了r1只检查EHM_AUTH_MODE导致的误拒绝。仍然要求Spring实际解析的认证模式为IAM，不放宽保护、不强制设置认证方式。模拟功能的新增参数以定向命令行参数提供，避免被现有JSON配置覆盖；没有新增认证、密码、SSO令牌或数据库凭据覆盖项。

部署收据仅包含版本、产物摘要、虚拟轮次及“账号/原数据未改变”校验结果，不包含密码。登录后的业务操作验收仍需系统负责人使用原账号完成，不把匿名401当成已验证实际登录成功。

### r3：采样时序与失败重试（2026-11-02）

r2采样校验只有约12秒等待，而调度器首次运行默认延迟15秒，存在首轮尚未执行就回退的风险。r3正常等待90秒；若已保留下一轮时间，则尊重原定时计划、最长等待390秒，不重置模拟时钟。只在轮次确实比升级前增加、虚拟采样实际增加至少87条、最新轮次87点且运行状态正常时通过。已有旧轮回执不能充当本次成功证据。

回退保留的虚拟记录在重试时不覆盖或重装。仅已核实属于发布包设备范围、存在模拟进度记录、标识匹配的虚拟设备实时快照和SYNTHETIC测点质量快照允许推进；其余原业务记录及所有账号仍逐条校验。暂停状态、失败状态不会被自动重启。`sampling-diagnostic.json`仅含轮次、数量、时间与错误类别，可用于排查，不含记录正文或凭据。r3本身不代表已成功部署，仍以服务器成功收据及实际验收为准。

### r4：安全策略兼容与统一页面验收（2026-11-02）

r3已在服务器观察到第2轮、174条虚拟采样，且通过原账号与业务数据校验，但统一首页校验失败后按设计回退。服务器SELinux为Enforcing，公共data目录及其中页面是default_t，直接作为Nginx静态alias存在访问策略问题。

r4后端JAR、公开源码、私有升级备份仍在公共`/data/projects/Project_B/`目录；只有清单中`web/`下的公开文件复制到既有`/var/www/project-b-unified/releases/<发布名>/ehms/`。新静态目录用restorecon恢复并逐一核对httpd_sys_content_t，仅该EHM新发布目录受影响，不关闭SELinux、不放宽全局策略、不对公共data目录递归改标签、不暴露私有发布备份。

Nginx配置原标签在原子替换时保留。重载后最多25秒等待，新建连接、禁止缓存，逐一验证首页及所有前端依赖的HTTP状态和SHA256，不再只查一句脚本文本。安全诊断`frontend-diagnostic.json`仅记录失败路径、HTTP状态、摘要与已验证文件数，不记录页面正文、Cookie、密码或令牌。源目录和服务器账号仍按原保护规则处理。最终仍以成功部署收据和真实登录验收为准。
