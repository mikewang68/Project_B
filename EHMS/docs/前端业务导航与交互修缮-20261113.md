## 1. 导航调整

日常导航收拢为五组、18 个常用入口，46 个已保留业务页面通过组内“相关功能”和功能搜索访问。

| 业务组 | 常用入口 | 相关功能示例 |
| --- | --- | --- |
| 工作台 | 综合驾驶舱、我的待办、班组交接 | 操作日志、数据运行状态、AI助手 |
| 设备与资料 | 设备台账与态势、设备档案、部件BOM、测点管理 | 校准记录、配置变更、设备模板、资产树 |

“数据与边缘、算法与模型、集成与系统”不再作为顶级导航。其后台代码、日志服务、模型服务和历史数据没有删除。没有业务入口的技术/规划页旧链接显示收起提示，不展示原型样例，不自动申请权限。

原 IAM 菜单键、页面路由和业务接口保持兼容；组内入口继续校验各页面自己的权限，父级分组不构成授权。

## 2. 详情与列表

- 设备详情提供“返回设备列表”和面包屑，保留原列表筛选、页码及滚动位置。
- 列表每页 15 台；筛选变化回到第 1 页，空结果与接口失败分开显示。
- URL 保存设备编码及详情标签，刷新后不会悄悄切换到第一台设备。
- 设备不在当前授权范围时明确提示；直接进入详情的返回入口回到台账。
- 详情按健康与趋势、部件与测点、技术与校准、维修工单、数字履历分组，基础字段改为响应式网格。
- 查看关联资料时继续按设备编码过滤；缺权限明确提示，不用空数组冒充没有业务记录。
- 从详情进入设备资料时跟随当前设备，避免展示上次选择的另一台设备。

## 3. 提交失败的处理

此前 `Write requires one authorized tuple` 来自服务端写范围限制，不是数据丢失或单纯的按钮样式错误。

保持服务端限制不变。前端增加安全预检，业务写入须符合：

1. 已登录且不是只读会话；
2. IAM 返回的范围来源为 `IAM_VERIFIED_CONTEXT`；
3. `mode=SCOPED` 且活动元组只有一个；
4. 元组的项目与当前项目一致，系统为 EHMS；
5. 原有菜单动作与业务权限仍须独立通过；后端是最终授权者。

全局、多范围或未确认范围的会话仍可按授权查询，但提交前会显示原因及统一门户入口。前端不伪造 scope、不把账号提权、不自动选择 EHMS_DEMO，也不移动 UNASSIGNED 历史数据。

表单失败保留输入并显示中文错误及跟踪号；异步保存期间原有提交禁用机制保留。修复通用错误清理误删业务校验占位的问题。工单必填项先校验，成功后进入工单中心并反馈编号、状态。不再使用固定的旧日期作为建议维护窗口。

错误提示框取消上下双定位，限制尺寸，避免拉成长条白色面板。

## 4. 文案与真实性

移除“组会可演示闭环”“功能恢复验证版”和无关的数据库实现文案。IAM账号显示统一授权身份，不以本地两级角色错误描述中央账号。

交接历史内容只改变展示：长文本显示短摘要，可展开完整转义原文；明细默认收起，数据库原文与历史审计载荷不修改。

保留虚拟数据标识、维护周期不是厂家寿命、RUL未验证、规则配置不等于现场引擎已生效、日志落库不等于上链等必要限制。
