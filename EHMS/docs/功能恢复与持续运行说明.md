# 功能恢复与持续运行（1.9.1 候选）

本次基于IAM V2.1交接基线修复，不回退统一身份体系，不移除项目、区域、系统数据隔离，也不清空业务记录。

## 页面与数据

- 驾驶舱恢复健康分布、区域分布和每日告警/工单变化图。图形只使用当前授权范围的后端聚合结果。
- 原菜单完整保留。已完成适配的功能按账号权限启用；未授权项标明“未授权”，未接入项标明“待接入”，不再整组悄悄消失。
- 恢复资产台账、BOM、测点、健康评估/历史/劣化趋势、维护建议、点检计划、维修闭环、备件、AI和本范围日志等已有功能的中央权限适配。
- 区域分布及统计报表继续复用原数据库图表；OEE、寿命预测、完整费用和资源预测等缺少输入或算法的指标继续说明边界，不生成假指标。
- 未适配的服务配置、公共日志证据导出、模型发布等仍保持关闭；不能因为角色叫“超管”就允许跨范围读取全模块数据。

## 保持“动起来”

既有模拟器、周期、累计工时、幂等号、告警阈值、工单和待办生成逻辑不重置。日常模式仍为每300秒一轮；实际以持久化设置为准，不强制覆盖用户已保存的间隔。

新增`GET /api/ehm/v1/system/activity`，只查询当前授权范围的数据数量和最后变化时间。它不启动、暂停、配置模拟器，也不补造停机期间历史。

前端每5秒观察变化，发现新业务数据才刷新相关页面；编辑表单、弹窗、抽屉或隐藏页面时暂缓。关闭网页不停止后台Java任务。

原模拟器仍遵守交接版`LEGACY_ONLY`范围守卫。V2人员不能通过旧全局模拟接口启动任务；已有后台任务独立持续运行。新增区域后台模拟仍需正式的服务身份与授权范围，不把人员会话借给定时任务。

## AI接入

- 保留后端模型适配器和原模型配置方式，不修改模型地址、Key、IAM账号或密码。
- 中央菜单键为`EHMS:ai-assistant`，需要`VIEW`；普通账号原生权限为`ehealth:wb:assistant:view`。不能仅给一个前端按钮就认为后端获准。
- 助手对每类工具分别检查源功能的VIEW和原生权限。例如拥有助手权限但没有工单查看权，就不能通过聊天读取工单。
- 数据范围仍由服务器可信上下文控制。选中范围外的设备会被拒绝，不向模型发送相应业务信息。
- 对话按用户、登录会话、项目、区域范围及授权版本隔离。切换身份/范围会清空前端旧结果；他人会话不能读取、复用或删除。
- AI只读问答允许获得VIEW的只读账号使用；保存待办、交接草稿仍要各业务的ADD权限及CSRF校验。
- 模型未配置或异常时明确显示本地检索，不伪装成已获得模型回答。实际模型连通仍需在目标环境使用原受保护配置验收。

## 日志

当前范围的日志入口不再读取全模块公共待投递队列。区域业务日志继承服务器核实的请求范围；只读用户的查询也可以产生基础设施审计记录，但不会获得业务写权限。

历史未知归属和多范围请求不推测区域；保留UNASSIGNED。公共AUDIT投递与链上回执机制不修改，本地日志不代表上链成功。

## 构建与验证

使用Java 17和Maven，安装仓库同版本的`IAM/context-client:2.1.0`与`AUDIT/client:1.0.1`，再构建EHMS。H2仅用于隔离测试；服务器普通构建不能启用`simulation-local` Maven profile。

```text
mvn -f IAM/context-client/pom.xml install
mvn -f AUDIT/pom.xml -pl client -am install
mvn -f EHMS/source/backend/pom.xml package
node --test EHMS/tests/*.test.cjs
```

可选真实浏览器检查：安装Playwright及Chrome后运行`node --test EHMS/tests/central-browser-smoke.cjs`。该检查使用合成HTTP夹具验证整套页面，不把它当成真实数据库、IAM或模型端到端联调。

测试报告与截图保存在本地`.local/verification/`，不作为公共配置提交。集成测试只能指向测试代码明确指定的内存库，不能指向业务数据库。

## 发布前必查

1. 只读确认当前服务器聚合表具备V2.1区域/系统列及主键；不自动清表或重复执行旧迁移。
2. 核对当前实际运行JAR与systemd覆盖配置，而不是根据页面版本文字判断版本。
3. 完整发布同版本web资源及JAR，保留原IAM、模型、数据库、审计、模拟周期与进度；使用既有安全标签合规的静态目录。
4. 确认原账号的中央菜单及原生权限已包含要启用的功能，尤其新增AI原生权限；未获授权时保持拒绝，不通过修改前端状态绕过。
5. 先验后台采样确实新增、原业务/账号记录保留、数据范围隔离有效，再验前端各资源摘要和真实登录。
6. 原r4安装器只识别旧部署形态，不直接把旧sudo命令用于该候选版。

本说明描述候选代码的行为，不声称候选版已经上传GitHub、部署服务器或完成真实模型调用验收。

## 候选包结构

`app/ehm-service.jar`是普通服务器构建产物；`web/`是完整同版本静态资源；`source-update/`是相对包内manifest所列基线的源码增量，不是完整仓库替换；`manifest.json`记录每个文件的SHA256。包内不含真实账号、环境变量、Key、本地数据库或自动安装器。不要把整个包覆盖到运行目录后直接重启，应先做上述发布检查。
