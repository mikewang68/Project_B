# EHMS 全功能演示与联动验收

日期：2026-11-17；版本：EHMS-integrated-demo-20261117-r2。

## 交付目的与使用区域

用于甲方线下核验业务流程，不把虚拟数据当作现场运行或最终需求签收。统一门户选择“设备健康独立演示区”（EHMS_DEMO），再进入EHMS。不要使用“全部获批区域”提交修改，也不要为凑数据跨区合并。SHEN_TIE、HA_TIE、UNASSIGNED原记录与原模拟任务不迁移、不清空；新任务只写PROJECT_B / EHMS_DEMO / EHMS。保留原账号、IAM菜单动作、AI密钥、公共MQ消费组及原始观测路径。

原空页不是“功能已经投入实际使用”的证明：沈铁演示设备仅有台账且缺测点，无法形成有效趋势/健康评估；历史持续模拟在UNASSIGNED。此次新增一条独立、可持久化的演示链，而不是前端静态数组。

## 本轮数据与自动更新

- 新演示任务复用设备范围目录建立29台带SAMPLE-LIVE标记的虚拟设备，关联部件、87个测点、计划、任务、模板、备件、风险条目。原有演示资产不覆盖；符合明确虚拟前缀的设备在缺项时补结构和资料，已有资料和公共MQ映射不覆盖。
- 为虚拟测点保存过去2小时、每5分钟一个源时间的24条初始历史，包括明确BAD质量样例。接收/生成时间为当前时间，来源DEMO_REPLAY_INITIALIZATION，模拟标记为true；不伪造当时已经实际运行或签核的历史。
- 独立演示任务默认每60秒运行，不依赖浏览器是否打开。每轮更新演示测点、质量、规则健康评估、快照与运行状态。累计演示工时每轮推进0.25小时，40小时为演示维护周期、80%为提醒阈值，不是设计寿命或RUL。
- 演示周期触发告警、站内待办和待审批工单；半个模拟日形成交接草稿，模拟日到期生成点检安排。已有未完成点检不重复派发；实际完成、审批、复测和关闭仍由授权用户操作，模拟器不代签、不自动推进用户工单。
- 初始预置6种维修状态：待审批、待执行、执行中、待复测、虚拟已关闭、复测失败。另有合格点检完成提醒的样例、点检缺陷和执行中的点检。预置审批/维修/复测人员明确标为虚拟场景服务，不冒充真实用户。
- 自动告警只根据标注的演示规则/数据质量形成；不宣称是现场故障。公共MQ事件可靠接收沿用独立worker，本轮不启动或重置公共生成器，也不将MQ模拟设备映射成已核定现场设备。

## 页面之间如何同步

设备台账与设备档案共用同一设备主表：新建成功刷新后可在档案选择器查到；删除操作采用归档，设备退出活动目录及统计，不物理清除维修和审计历史，演示任务跳过归档设备且不重建。已打开设备变化时清理旧档案缓存，避免新设备标题下短暂显示上一台资料。

维保日历是只读投影，不单独造一份记录：从当前授权区域的maintenance-plan、inspection-task、work-order、work-order-repair和maintenance-case读取计划日期、点检安排/提交、工单状态变化、维修执行、复测和恢复结论。操作后进入“维保计划 / 日历”，选同设备和月份即可回查；日期和类型均可筛选，维修档案有入口。缺少工单或维修查看授权时不读相应明细，不放大权限。

复测失败可点击“返修 / 补充执行”返回执行中，补记实际执行后再提交复测；旧轮次通过结果不能关闭新轮次。暂停可恢复、审批可驳回。流转须填写实际依据，服务端仍验证状态机、登录身份、动作和单一区域。

## 明天线下推荐核验顺序

1. 登录原账号→门户选“设备健康独立演示区”→EHMS确认“当前可写区域：EHMS_DEMO”。先选择带SAMPLE-LIVE前缀的完整虚拟设备。
2. 看台账、资料、BOM、测点；新增一台标记“验收”的虚拟设备，在档案中查到，再归档验证活动目录同步（不要归档正在演示的主设备）。
3. 实时监测查过去2小时并导出；确认BAD样例与模拟标记，1分钟后最新采样时间变化。
4. 健康页说明规则因子和限制，运行/查看有效评估。审核需对应IAM动作，不以超级管理员名义绕过中央菜单权限。
5. 告警→证据→历史窗口→人工结论/修订；保留明确的真实登录操作记录。
6. 工单从待审批走完整维修闭环，先故意漏测或填“不通过”，确认不能关闭；补充执行/新轮次复测后复核。
7. 维保计划/日历选同设备/当月，筛选维修执行和量化复测，应看到刚才的实际输入，而不是固定样例。点检、提醒与交接查看持久记录。
8. KPI按当前区域的实际台账/告警/工单统计；核对数量，不能把全区域总数与单一区域混比。

## 发布与边界

增量包针对实际运行JAR编译，只替换列明类和页面资源，其余JAR条目、上游公共MQ补丁、IAM和AI资产逐字节保留。启用新的独立演示任务，不替换旧模拟配置。发布前对EHMS_DEMO当前数据做私有只读快照（文件权限600）；初始化只增补演示数据，不清表、不修改其他区域。初始化失败则回退应用与入口，已经提交的演示数据/审计保留，不作破坏性数据库回滚。

自动测试、持久数据校验与线上登录验收分别记录。仍未具备现场真实运行、厂家正式阈值、经过验证的寿命模型、独立岗位制度及DTS两端最终签收的证据，不能以演示数据代替这些验收。

## 本轮测试记录

后端294项、前端160项、发布校验/回退10项均通过，失败/错误/跳过为0；实际候选静态资源的浏览器回归通过（真实HTML/JS+隔离HTTP测试端）。后端测试包含独立H2数据库的关联初始化、重复启动去重、新增/归档同步、维修日历投影、失败复测拒关、质量和模拟来源保留、跨区隔离、公共MQ映射不被写入真实时序适配器、演示任务不因旧本地演练轮数上限而暂停。

服务器只读预检通过：15个类和6个静态资源增量；其他JAR条目与公开资源保留。现网openGauss初始化及最终登录验收以正式发布回执为准，不用本地测试结果冒充已写入现网。

## r2实际发布类集回归

r1现网初始化在创建simulation-control之前被旧版SimulationBackgroundPolicy拒绝；源码已有DEMO_SERVICE支持，但增量包遗漏该依赖类。r2显式增加该类，清单为16个类，并校验候选类包含DEMO_SERVICE契约。使用r2候选JAR直接解出的全部BOOT-INF/classes替换测试运行时类集（不重新编译业务源码），6项DemoWorkspaceIntegrationTest全部通过；其中包含持久关联初始化、去重、台账/档案新增归档、维修日历、失败复测拒关、来源与跨区隔离、公共MQ不写入真实时序、旧演练轮数上限不停止区域任务等路径。原源码294项回归与候选包6项集成验证分开记录，不把外置worker源码测试冒称服务JAR内置功能。

r2另通过11项发布/回退/边界检查。发布等待器允许旧进程遗留FAILED状态在新调度首轮前存在，避免尚未运行新任务就误判失败。首次失败已回退原应用，保留原业务数据；留下的失败状态记录不删除。
