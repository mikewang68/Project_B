# EHMS需求工作簿对齐：本地实现与验收说明

依据：董博涵《系统需求功能工作簿.xlsx》v2.0，2026-11-14；范围为R-E01～R-E08及其20个EHMS功能定义，另有2项DTS协作关系。

本轮是代码实现，不是甲方最终签收。未修改原工作簿、服务器、GitHub、IAM权限、账号密码、生产数据和原模拟任务配置。新增功能需前后端配套发布，不能直接复用上一次“仅前端增量发布”命令。

## 一、已经落地的主要变化

1. 告警确认、分派、关闭；工单创建及状态推进；人工诊断、维修执行、复测、闭环；健康评估审核、转单；点检开始、提交、缺陷转单；待办完成和交接班提交、接收，其业务签名改为服务器验证的登录身份。兼容保留请求中的operator/reviewer字段，但不信任它们代签。
2. 告警关闭理由必填；有关联未闭环维修档案时，不能从告警列表提前关闭而破坏维修流程。
3. 时序正常线在BAD、STALE和缺值处断开，异常质量原值单独标注；缺值不补零。公共MQ记录从已保存的原始观测读取事件ID、模拟标志和来源定位，不冒称openGemini现场数据。
4. 支持任意起止时间，单次最多90天、2000条；源时间、接收时间分别显示。空结果、查询失败和范围无效分别反馈。
5. 告警列表真实筛选、分页、类型区分和状态履历；规则事件不直接称为已确认物理故障。
6. 通用工单状态接口禁止直接CLOSED。告警来源工单继续走原闭环档案；手工、点检、健康建议来源工单增加独立维修档案，同样要求真实执行、计划内复测和复核结论。
7. 复测点必须属于该设备、启用且单位一致；必测计划内所有测点，本轮最新结果均通过后才允许关闭。返修后旧轮次的通过结果不能代替新复测。
8. 设备恢复决定单独保存为AVAILABLE／RESTRICTED／NOT_RESTORED，并记录依据、限制条件与复核人。工单关闭不改PLC，不自动改设备可用状态或生产计划。
9. 维护依据到期后可生成持久、去重待办。不能直接勾选完成；须关联该设备、本提醒之后的合格点检，填写覆盖维护条款的复核说明；工时／次数周期须给出有效累计完成读数，才回填维护周期。
10. 可选演示区自动扫描默认关闭；启用后默认15分钟检查一次，只处理PROJECT_B／EHMS_DEMO／EHMS中来源为SIMULATED的维护依据，不扫描历史UNASSIGNED或真实业务区域，不自动派维修单。
11. 可将历史时间窗实际记录固化为带SHA256的证据，并保留质量、时间、原事件定位。明确这是“现在回查固化的历史”，不是虚构“异常发生当时已冻结”。人工诊断支持追加修订链及原因，不覆盖旧结论。
12. 所有测点统一拒绝无有效阈值的规则评分；输入窗口只统计实际评分因子。历史回放及过期结果不可作为当前审核／转单依据。评估审核和转单增加同库事务及行锁，避免并发重复转单和保存失败遗留孤立工单。
13. 新增逐设备健康摘要只读API。无评估或已过期时返回UNKNOWN／STALE和空分数，不用台账健康分冒充有效评估，也不把未知当作健康。

## 二、使用人员、输入与正常业务流程

|需求|使用人员与责任|必须输入／提供的信息|本地已支持的正常流程及异常约束|
|---|---|---|---|
|R-E01 设备资料|设备管理员维护、运维人员查询|统一设备编码、部件与测点编码、单位、资料版本及来源|选设备→查部件/测点→核对资料；未知厂家参数保留缺项，未绑定不换成其他设备|
|R-E02 时序质量|运维人员查询、工程师分析|设备、测点、起止时间；接入侧提供源时间、质量、模拟状态与事件信息|查已保存历史→区分质量/缺值→查看来源；错误不当空数据，超过范围需缩短窗口|
|R-E03 告警处置|设备管理员确认/分派，运维人员处置，授权人员复核|告警编号、实际处理理由；系统保留触发信息与状态履历|定位→确认→处理→复核关闭；采集异常不推断物理故障，维修档案未闭环不能旁路关闭|
|R-E04 维护周期|设备管理员登记依据，责任班组执行，授权人员复核|本设备有效资料版本、条款、周期/提前量、责任班组、日期或累计读数；完成时提供实际点检及覆盖说明|核算→生成去重待办→按计划点检→合格结果人工核对→回填周期；缺资料/读数不自动猜测到期|
|R-E05 维修履历|维修人员执行、复测人员测量、授权人员复核|工单、维修动作、结果、安全措施、备件、必测点、前后值、单位、判据、恢复决定与依据|审批→执行→待复测→量化复测→复核关闭；缺项/失败保持未闭环，恢复决定不等于设备启动许可|
|R-E06 证据分析|设备工程师/分析人员，授权人员复核修订|告警、同设备测点、历史窗口、现场证据、人工结论与原因；修订须提供原记录及理由|建档→固化实际历史→人工分析→追加修订→回看原始和修订链；无历史不拿当前快照补造|
|R-E07 健康建议|工程师解释评估，授权人员审核/转单|有效GOOD因子、有效阈值、输入时间、限制说明、审核决定与意见、工单责任班组和窗口|规则评估→解释因素和限制→人工审核→接受后转待审批工单；无阈值/过期/回放不作为当前维修依据|
|R-E08 DTS摘要|EHMS提供受权查询，DTS负责人负责消费展示|同一项目/区域/设备编码、已保存评估、有效期、质量覆盖、数据性质及未知原因|查询摘要→DTS按状态展示→受权详情回看；不在GET上触发推理或写数据，不把总数接口当逐设备摘要|

这些是业务职责，不是本轮新建的IAM角色。实际动作仍需当前IAM菜单动作及EHMS原生权限共同允许；未擅自授予其他人员权限。同一账号持有多项动作时技术上可操作多步；“维修人与复核人必须不同账号”等强制职责分离规则仍须甲方与IAM负责人确认后配置，不能声称已完成组织制度验收。

## 四、验收建议

使用隔离的测试/演示区域，不在正式设备上填虚拟结果：

1. 实时监测：选测点，输入实际历史时间窗，查看GOOD、BAD、STALE和缺值；确认正常线断开，明细与导出能追溯时间、事件和模拟标志。
2. 告警中心：筛选设备和类型，查看履历；确认、分派和关闭后检查操作者为登录账号，空关闭理由必须失败。
3. 维护计划与任务：先在设备档案上传或登记明确标识的虚拟维护说明与周期；核算到期两次只生成一次待办；直接勾选完成应被拒绝；真实提交合格点检后，填写条款覆盖说明关联完成，检查周期更新。
4. 工单中心：打开“维修/复测/履历”；登记本设备必测计划，执行中保存实际动作，推进到待复测。少测一个点、最新失败、错误单位或其他设备测点均不得关单；补齐后记录复核结论和恢复决定。
5. 告警证据：固化同设备历史窗口，回看SHA256、质量与原事件；追加人工诊断修订后原记录仍在。
6. 健康建议：无有效阈值不得得分；过期/回放不能审核转当前维修单；对有效且人工接受的评估重复转单，应仍关联同一工单。
7. 健康摘要：同设备核对assessmentId、sourceTimestamp、generatedAt、validUntil；无评估/过期时分数必须为空。换其他区域后不得出现前一区域记录。

## 五、测试证据与发布边界

测试命令：后端`mvn -o test -q`；前端`node --test tests/*.test.cjs`；浏览器`node --test tests/central-browser-smoke.cjs`。

本轮最终结果：后端285项通过，前端146项通过，浏览器页面及维修表单端到端流程测试通过；失败/错误/跳过均为0，`mvn -o package -q`打包通过，`git diff --check`通过。

本地后端构建产物：`source/backend/target/ehm-demo-0.1.0.jar`，SHA256为`dc4296fde1a741bb71fda80e0b1ed3807f884320dc823074c47abdd71081b3e2`。此摘要仅用于识别本地测试产物，不代表已做现网升级或可直接替换独立公共worker。

后端包含隔离H2数据库的业务事务、并发、去重、区域隔离和证据保真测试；浏览器使用真实HTML/JS与合成HTTP测试端验证页面、表单、失败保留输入和操作入口。它们不是生产openGauss、公共MQ、实际IAM登录或真实大模型联调证明。

本轮不执行服务器发布，不修改生产数据，不重置公共消息，不调用真实AI，不声称新操作已完成公共AUDIT投递或链上确认。旧模拟器、独立公共接入worker以及AI配置均保留。后续发布须单独准备前后端配套增量包、验证现网公共接入补丁兼容性并安排登录验收。
