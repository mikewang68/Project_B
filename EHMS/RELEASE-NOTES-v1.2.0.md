# EHM 可交付演示版 v1.2.0

## 本次完成

- 按六大模块规范统一为“深海军蓝导航 + 浅灰蓝背景 + 白色内容区 + #409EFF 品牌蓝”。
- 修复设备、告警、工单分页响应被当作数组读取的问题。
- 设备台账具备新增、查询筛选、编辑、查看和受控归档。
- BOM部件具备新增、查看、编辑和受控归档。
- 测点具备新增、查看、编辑、样本录入、数据质量判定和受控归档。
- 告警支持确认、关闭和转工单；工单支持创建及状态推进。
- 维护计划、点检、缺陷、备件和可靠性治理继续使用现有真实后端业务接口。
- 未完成入口不再提示“已接入后端服务”或伪造成功，而是明确说明本轮演示边界。
- 新增表单必填校验、危险操作确认、提交中状态和重复提交保护。
- 所有旧MongoDB展示文案更新为服务器实际采用的openGauss/openGemini架构。

## 服务器验收

应用启动后执行：

    chmod +x bin/*.sh
    ./bin/check-ehm.sh
    ./bin/smoke-crud.sh

最后出现下列文本即说明基础链路通过：

    EHM CRUD_SMOKE_OK：openGauss业务CRUD和openGemini样本链路已通过。

脚本只创建带“QA-时间戳”的临时设备、部件和测点，完成后按“测点→部件→设备”顺序归档，不修改正式设备数据。

## 组会建议演示顺序

1. 资产中心 → 资产树与设备台账：新建设备、搜索、编辑、打开详情。
2. 资产中心 → 部件BOM：新建和编辑部件。
3. 资产中心 → 测点管理：新建和编辑测点、录入样本。
4. 数据与边缘 → 数据质量：查看样本质量判定和健康评估门槛。
5. 告警与诊断 → 实时告警中心：确认告警、转工单。
6. 维保管理 → 工单中心：新建工单并推进状态。
7. 维保管理 → 维保策略/点检/备件：展示计划、任务、缺陷和库存流水。
8. 可靠性治理：展示FMECA、规则发布、知识案例审核和SLA编辑。

## 业务删除规则

- 设备、BOM和测点执行“归档”，历史告警、工单、样本和审计记录保留。
- 告警执行“确认/关闭”，工单执行“取消/关闭或状态推进”，不提供物理删除。
- 这些约束用于满足工业系统追溯和审计要求。
