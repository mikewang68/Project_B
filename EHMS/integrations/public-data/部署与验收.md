# 部署、停止、补传与验收

## 1. 前置条件与边界

- Java17；重新构建需要 Maven。worker 无 Spring Web 启动过程，不监听 HTTP 端口。
- 只使用 EHMS 的真实业务库连接；现有聚合表要存在，列为 `project_id,region_id,subsystem_code,aggregate_type,aggregate_id,payload,updated_at`，主键包含前五列。
- 由负责人/DBA确认 `PROJECT_B / EHMS_DEMO / EHMS` 已按原生流程登记，并给验收账号相应区域查看权限。worker 自己不向 IAM 申请、修改或放宽权限。
- 使用独立私有配置及数据库身份；身份应只访问 EHMS 所需库表。不要复用 IAM 管理员口令，不把凭据写入本包或 Git。
- 停掉同一 sourceId 的旧 worker 后再更换版本。HTTP/MQ 可共用同一 sourceId，行锁序列化业务事务；不为同一目标区域另起不同 sourceId 的并行写入器。
- 默认不安装定时任务。包中的示例配置 `enabled=false`，必须负责人检查后在私有副本显式打开。

## 2. 隧道

在董博涵原交接包的解压目录执行，不改变 PowerShell 执行策略：

```powershell
ssh -F .\personal-ssh.conf -N -L 127.0.0.1:38121:127.0.0.1:38121 -L 127.0.0.1:39887:127.0.0.1:39887 -L 127.0.0.1:39921:127.0.0.1:39921 personal-bn5
```

保持窗口打开。隧道与 worker 必须在同一侧环境（Windows 或 Linux/WSL）；MQ broker 通告的 `127.0.0.1:39921` 不可省略。服务器部署时用管理员批准的服务器侧通路，不在包内硬编码跨主机账号密码。

## 3. 私有配置

复制 `config/worker.config.example.json` 到**交付目录的 config 下的私有副本**（相对 mapping 路径按配置文件所在目录解析）；也可以放在 `/etc/ehms-public-data/`，但相应把 mapping 两个路径改为绝对路径。

实际填写数据库 URL/专用用户、密码文件路径、HTTP token 文件路径。密码文件在 Linux 限制到 worker 账号可读（600），其父目录不可公开；Windows 使用专用受限目录。HTTP token 与 MQ client 文件取董博涵原包，**不用重新发送给任何人**。

检查 target 为 EHMS_DEMO、表名/库名正确、目录摘要没有被改动，再把私有副本 `enabled` 改为 true。配置里不能有 ALL/UNASSIGNED 通配。更换身份、策略、作用域或目录版本会触发绑定拒绝，应停止旧消费器并设计新 sourceId/重放迁移；禁止手工修改旧游标绕过校验。

## 4. 初始化与 HTTP 补读

在本包根目录，Windows classpath 使用分号：

```powershell
java -cp "bin/ehms-public-data-worker.jar;lib/*" com.bproject.ehm.publicdata.PublicDataMain config/worker.private.json init
java -cp "bin/ehms-public-data-worker.jar;lib/*" com.bproject.ehm.publicdata.PublicDataMain config/worker.private.json http 60 100
java -cp "bin/ehms-public-data-worker.jar;lib/*" com.bproject.ehm.publicdata.PublicDataMain config/worker.private.json status
```

Linux 把 `;` 改成 `:`。`init` 只新增本 worker 的四张 `ehms_pd_*` 辅助表和索引，不改现有表结构，不清空数据。不具备 DDL 权限时由 DBA 用短期受限维护身份执行初始化，再换回 DML 身份。

`http 60 100` 最长发起约 60 秒的有界补读，最多接纳 100 个新事件；正在进行的单次 HTTP/数据库调用有自身超时，结束时间可能略晚。不修改公共生成器；空页不会推进游标、不会不断忙轮询。同一命令再次执行从已提交游标继续。

## 5. 正式 MQ 消费

`mq-lib` 中使用董博涵原交接包 `RocketMQ/lib` 的 JAR；这些库只供独立 transport 使用，不拷进正在运行的 EHMS web 应用。

```powershell
java -cp "bin/ehms-public-data-worker.jar;bin/ehms-public-data-mq.jar;lib/*;mq-lib/*" CommittedMqMain config/worker.private.json "原交接包/凭据/mq-client.json" 60 100
```

topic/group/principal 必须对应 EHMS 正式分配。首先通过 HTTP、数据库事务测试及 `init/status`，然后才连接正式组；不要用官方组运行只打印消息的临时程序。MQ 接收箱事务提交后 ACK；业务处理失败留箱重试，不伪装 APPLIED。内容冲突进入持久隔离箱并 ACK，**该 ACK 只表示已可靠隔离，不表示业务成功**；HTTP 遇同类冲突则停止推进该条游标。

首次实际 MQ 验收需要董博涵协调一条新模拟提交；不由本包擅自开公共生成器。不把“消费者成功启动但收到 0 条”写成落箱/业务入库通过。

## 6. 停止、重启与补偿

- Ctrl+C 或等待设定时长/条数结束即可停止；进程退出后不会自己重新启动。
- 再次用同一配置运行，可恢复已提交 HTTP 游标与 MQ 组进度。PENDING、失败未达 10 次的记录可由 `process` 重做。
- 业务失败时业务事务回滚，60 秒后再试；超过 10 次保留失败记录，修复映射/权限/数据库问题后用 `retry` 重置失败尝试次数，再用 `process`。隔离箱不自动清除、不自动覆盖冲突事件。
- 接收箱积压达到 10,000 条 PENDING/FAILED 后拒收新事件：MQ 不 ACK、HTTP 不前移，先处理积压。需要监测长期历史容量并另行确认归档保留期；本包不执行删除。

```powershell
java -cp "bin/ehms-public-data-worker.jar;lib/*" com.bproject.ehm.publicdata.PublicDataMain config/worker.private.json process
java -cp "bin/ehms-public-data-worker.jar;lib/*" com.bproject.ehm.publicdata.PublicDataMain config/worker.private.json retry
```

## 7. 页面与业务验收

1. 只对目标 EHMS 后端应用 `ehms-web-patch/EHMS-public-data.patch`，先 `git apply --check`，不要覆盖目录。构建回归后按现有安全发布流程上线；本包不自带一键替换生产系统的脚本。
2. IAM 原账号重登并明确选择 EHMS_DEMO。在设备台账查 `MQ-SIM-` 设备，查看采集组/测点、数据质量、实时历史。没有该区域权限应继续 403，不得读其他区数据补空。
3. 原始观察/资产引用在 `committed-observation`、`committed-latest`；标量历史在 `committed-telemetry`。源 BAD/未知/空值的质量评估不得 GOOD；历史补读不能显示为实时正常。
4. 真实厂家阈值/工程演示阈值需经确认后在现有测点配置里设置；默认不产生健康分/RUL。字符串、布尔、枚举默认不参与数值评估。
5. 收到 BAD/STALE 后，告警中心可查询 `MQ-Q-` 的“采集质量异常”；同一持续异常不按样本重复创建。此告警按原 UI 执行人工确认/核查，不自动批准工单。
6. 对同一事件再次 HTTP/MQ 投递，业务记录不重复；杀掉已落箱未处理的 worker 后重启，PENDING 仍能处理；人为制造 SQL 失败后不应留下半套设备/测点记录。生产演练需管理员同意，不在真实库随意故障注入。

## 8. 只读 SQL（以实际配置为准）

```sql
SELECT status, count(*) FROM ehm.ehms_pd_inbox
 WHERE source_id='ehms-public-v1' GROUP BY status;
SELECT reason,count(*) FROM ehm.ehms_pd_quarantine
 WHERE source_id='ehms-public-v1' GROUP BY reason;
SELECT aggregate_type,count(*) FROM ehm.aggregate_store
 WHERE project_id='PROJECT_B' AND region_id='EHMS_DEMO'
   AND subsystem_code='EHMS'
   AND aggregate_type IN ('asset','measurement-point','committed-observation',
      'committed-telemetry','committed-business-receipt','point-quality','alarm')
 GROUP BY aggregate_type;
```

查询原文需按事件 ID 且具备数据权限，不把 private 配置、原文、token 贴到公开群。原始 `raw_body` 是 Base64，不是明文 JSON；先解码再做接收字节摘要检查。

## 9. 回退

停止新增 worker，恢复 EHMS 这两处代码的已备份版本；不要恢复整库、不要删除业务记录/接收箱、不要重置 MQ 组 offset。新增设备/记录有独立编码与作用域，可在授权范围内排查，原 SAMPLE-LIVE 定时任务和已有账户保持原样。

## 10. 需要持续接收时（默认不启用）

代码包还附 `deploy/*.example`，供真实端到端验收通过后由管理员审阅再安装，不是自动部署脚本。受限 worker 用户、私有配置、已有数据库连接及服务器侧长期网络通路均须先就绪，特别是 systemd 不会继承开发人员电脑上的 SSH 隧道。

模板为每轮最多900秒/5000次接收，轮次结束30秒后继续；MQ 以持久 group offset 和数据库 inbox 恢复，不是每轮清空。只接收/处理公共事件，不启动公共生成器。不需要浏览器保持打开。

管理员确认路径/身份后，才将 `.example` 审核为本机真正的 `.service/.timer` 并显式 enable。停止后续轮次用 `systemctl stop ehms-public-data.timer`，停止当前轮次还要 `systemctl stop ehms-public-data.service`；临时不再使用时 disable timer。验收前不要自动启动；本次没有安装/启用这些 unit。
