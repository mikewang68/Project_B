# 设备健康管理系统（EHM）Demo统一服务器部署说明

## 1. 交付内容与边界

本压缩包包含前端、Java后端、MongoDB容器编排、Nginx配置、统一配置模板和演示初始化数据。MongoDB数据卷不在压缩包内，因此在新服务器首次启动时会生成一套干净的演示数据。

当前版本用于六个系统在同一实验室环境中的联调验证，不是生产发布版本。登录鉴权、RBAC强制校验、真实PLC/传感器采集、审批签名、RocketMQ事件流、生产级时序库和AI模型训练尚未启用。

## 2. 服务器最低条件

- 操作系统：推荐Linux x86_64；Windows服务器也可使用Docker Desktop或Docker Engine兼容环境。
- Docker Engine：24或更高版本。
- Docker Compose：v2或更高版本。
- 最低资源：2核CPU、4 GB内存、10 GB可用磁盘，仅供单人功能验证。
- 推荐资源：4核CPU、8 GB内存、20 GB以上可用磁盘，适合多人并行演示与接口联调。
- 网络：首次在线构建需访问Docker Hub和Maven Central；离线服务器见第8节。

## 3. 默认服务与端口

| 服务 | 容器内端口 | 默认主机端口 | 用途 |
|---|---:|---:|---|
| EHM前端/Nginx | 80 | 8088 | 用户访问入口 |
| EHM后端/Spring Boot | 8080 | 8080 | API与健康检查 |
| MongoDB | 27017 | 27017 | Demo业务数据库 |

六套系统同机部署时必须先登记端口。如果发生冲突，在`.env`中修改`EHM_WEB_PORT`、`EHM_BACKEND_PORT`或`MONGO_PORT`，不需要修改源码。

生产网络或共享服务器上只建议对业务访问网段开放前端端口。8080应限制为运维或网关访问，27017不应对互联网开放。

## 4. Linux服务器部署

将压缩包上传至服务器后执行：

```bash
unzip B项目-设备健康管理系统EHM全栈Demo-v0.1-20260904.zip
cd EHM智能展示原型-v3-light
cp .env.example .env
```

编辑`.env`，至少修改MongoDB密码和冲突端口：

```text
MONGO_ROOT_USERNAME=ehm_admin
MONGO_ROOT_PASSWORD=请替换为服务器专用强密码
MONGO_PORT=27017
EHM_BACKEND_PORT=8080
EHM_WEB_PORT=8088
```

启动：

```bash
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:8080/health/ready
```

健康检查应返回`status=UP`和`mongo=UP`。浏览器访问：

```text
http://服务器IP:8088
```

## 5. Windows服务器部署

在解压目录打开PowerShell：

```powershell
Copy-Item .env.example .env
docker compose up -d --build
docker compose ps
Invoke-RestMethod http://127.0.0.1:8080/health/ready
```

浏览器访问`http://服务器IP:8088`。

## 6. AI API接入

不配置AI API时，系统自动使用Java后端的规则回答，主要功能仍可演示。接入兼容OpenAI Chat Completions格式的服务时，在`.env`中增加：

```text
EHM_AI_ENABLED=true
EHM_AI_BASE_URL=https://服务地址/v1
EHM_AI_API_KEY=真实密钥
EHM_AI_MODEL=模型名称
```

然后只重建后端：

```bash
docker compose up -d --build backend
```

真实密钥只能放在服务器`.env`或后续统一密钥管理系统中，不要写入`.config.json`、前端文件、压缩包或代码仓库。

## 7. 六系统统一环境建议

- 使用统一反向代理或Easegress，仅暴露一个平台入口；EHM建议使用固定路径前缀`/api/ehm`。
- 六个系统分别使用独立Compose项目名、容器名、数据库和数据卷，避免互相覆盖。
- 统一登记前端端口、后端端口、健康检查地址、日志查看命令和责任人。
- EHM后端健康检查：`/health/live`和`/health/ready`。
- 当前Demo内置MongoDB。后续接入实验室openGauss、openGemini、Kvrocks、RocketMQ和Nightingale时，应逐项启用，不能同时把所有中间件设为启动硬依赖。

## 8. 离线服务器部署

如果统一服务器不能访问互联网，可在已经成功构建的联网电脑上导出运行镜像：

```powershell
docker save -o ehm-demo-images.tar ehm-demo-frontend:latest ehm-demo-backend:latest mongo:7.0
```

将源码压缩包和`ehm-demo-images.tar`一起传到服务器，执行：

```bash
docker load -i ehm-demo-images.tar
cd EHM智能展示原型-v3-light
cp .env.example .env
docker compose up -d --no-build
```

镜像文件通常较大，本次源码压缩包不包含镜像包。

## 9. 常用运维命令

```bash
# 查看状态
docker compose ps

# 查看后端日志
docker compose logs -f --tail 200 backend

# 重启全部服务
docker compose restart

# 停止服务但保留MongoDB数据
docker compose down

# 更新源码后重新构建
docker compose up -d --build
```

禁止在需要保留数据时执行`docker compose down -v`，该命令会删除Demo数据库卷。

## 10. 验收检查

部署后依次确认：

1. `docker compose ps`中的MongoDB状态为`healthy`，后端和前端均为`Up`。
2. `/health/ready`返回后端与MongoDB正常。
3. 页面右上角显示“Demo后端已连接”。
4. 驾驶舱能读取8台初始化设备。
5. 告警可以确认或关闭，刷新后状态保留。
6. 工单可以创建并推进状态，重启后端后数据仍保留。
7. AI助手在未配置外部API时返回`rule-demo`模式答案。

本项目资料按项目保密要求流转，压缩包、服务器地址、数据库口令和API密钥不得上传公共网盘或公共代码仓库。
