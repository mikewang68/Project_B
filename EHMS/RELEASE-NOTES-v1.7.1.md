# EHM 1.7.1-server：日志覆盖与诊断完善

日期：2026-10-14。基于1.7.0公共日志接入版本继续完善，只改EHM，不修改IAM/SYS/TRUST。

## 已补充

- 日志使用Spring实际匹配路由及对象变量，不再将reliability等类别错当对象编号；已覆盖assessmentId、pointCode等现有路径变量。未知/被拒绝路径只保留类别及占位符，不直接保存任意路径尾部。
- 区分新增与交接提交/接收、备件入库/退回、巡检提交、诊断及复测等业务执行动作。
- 本地旧审计写入与公共队列入队分别执行，前者故障不会阻断后者。
- 显式ResponseEntity/响应状态拒绝不会被记录为成功；事务中的变更回滚。未捕获异常由请求过滤器记录失败。
- AI接口新增独立审计，不在模型网络调用期间持有业务数据库事务。连通性返回success=false和local-fallback记FAILED；正常本地检索local-data仍是成功处理，不冒充模型回答。日志不含问题和回答原文。
- 401/403在本地审计及公共日志中区分DENIED；成功客户端事件不重复生成公共请求事件，失败或拒绝的客户端事件入口仍留痕。
- /system/audit-delivery返回最近20条事件的有限元数据和投递状态，增加本进程启动以来入队异常计数/最近时间；不返回payload正文、服务凭据或回执原文。
- 操作日志页面增加事件明细：动作、模块、对象、用户、操作结果、投递状态、事件编号和追踪号；入队异常有醒目提示。
- 角色下拉框明确仅为设计预览，不修改可信身份或后端权限。审计证据包文案改为“接口操作”，不再误称所有记录为写操作。

## 当前覆盖边界

| 范围 | 实现方式与限制 |
| --- | --- |
| 设备、部件、测点、模板、校准、配置履历 | 已有核心控制器由事务审计切面覆盖；不是承诺每个菜单均已开发完成 |
| 告警、工单、维修闭环、巡检、维保计划 | 已有控制器的查询、命令与拒绝/失败留痕 |
| 我的待办、班组交接、备件库存、可靠性治理 | 已有控制器同事务入队，业务执行动作分类完善 |
| 健康评估、遥测、数据质量、统计 | 查询/命令留痕；时序库等外部资源不与openGauss构成分布式原子事务 |
| AI助手 | 请求元数据与降级/测试失败识别；不记录对话正文 |
| 浏览、浏览器端导出 | CLIENT/STARTED意图，不作为文件生成/下载完成证据 |
| 登录、角色授权 | 等IAM真实会话联调；未验证用户记anonymous，不新增独立假登录 |
| 备份、恢复、训练等后台任务 | 公共SDK有JobAudit，EHM没有新增真实任务执行器；不能宣称这些任务已经实现或覆盖 |
| 区块链 | 待区块链负责方联调日志专用契约；ACCEPTED只代表公共日志入库，不代表上链 |

## 升级说明

1. 保留服务器私有配置，不替换数据库密码、模型配置及Token。
2. 首次从1.6.x升级仍需执行sql/002_audit_outbox.sql；已完成1.7.0迁移的，本次无需新增表。
3. AUDIT公共SDK先mvn install，再构建EHMS/source/backend；使用Java17。
4. 替换本次新构建的EHM jar及web目录，不能只复制源码或沿用旧app目录jar。
5. 保持未确认的链适配关闭。按下述本机验证范围和服务器验证清单核验，不把本机H2结果当成现场openGauss证明。

本轮未推送GitHub、未部署服务器，旧EHM智能展示原型-v3-light目录没有覆盖。新增队列明细接口仍依赖现有身份/访问控制配置，完整业务RBAC和日志读取授权需要与雷文联调，不应直接开放公网。
