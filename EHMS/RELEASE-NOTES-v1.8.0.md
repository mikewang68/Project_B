# 1.8.0-server：账号登录与两类访问权限

新增本地账号登录、退出、查询本人身份、修改本人密码，以及超级管理员账号创建、编辑角色/状态、重置其他账号密码。一般用户可查询业务数据、使用只读AI问答、查看本人日志；业务写入、后台执行、敏感导出和账号管理由超级管理员执行。前端禁用受限按钮，后端独立执行401/403校验，不能用浏览器角色字段越权。

账号、会话和登录限速保存在既有openGauss，需先执行`sql/004_local_auth.sql`，自定义schema/前缀须一致替换。密码使用随机盐PBKDF2-HMAC-SHA256（600000轮）；不保存明文，不提供默认公用密码或开放注册。仅空账号库从私有`EHM_AUTH_BOOTSTRAP_FILE`初始化。数据库运行身份不需要账号表DELETE权限；会话撤销/过期及限速清理需要相应DELETE权限。

会话使用HttpOnly/SameSite=Lax Cookie、8小时绝对过期和30分钟空闲超时，写请求要求同步CSRF令牌。角色变更、停用或密码修改撤销相关会话，不能停用/降级当前管理员并保留至少一名有效管理员。登录成功/失败、退出、拒绝及账号管理进入既有日志链路，不记录密码、Cookie或CSRF原文。

服务器默认`EHM_AUTH_MODE=local`。如改为`iam`，本地登录/账号管理不接管IAM；后台角色只采信已验证IAM响应，只有受支持的SUPER_ADMIN角色可执行写操作，可信只读优先。该模式仍需真实IAM联调。`disabled`只供明确隔离的旧契约测试，不可用于共享环境。

正式HTTPS部署保持`EHM_AUTH_COOKIE_SECURE=true`，Origin精确允许列表不变。HTTP/SSH隔离预览可显式设false。不同本机验收实例使用不同Cookie名称，避免同主机端口间Cookie冲突。没有将本地账号声称为平台SSO，也未变更其他模块的用户权限。
