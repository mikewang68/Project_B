# SCS 中央范围迁移

按 `001-central-scope.sql` → `002-resource-scope.sql` 执行。两个脚本只改结构，不创建账号、发放权限、注册机器来源或补业务归属。先确认目标库/schema、应用版本与备份；连接信息通过部署方私有配置提供，SQL 客户端须启用遇错停止。

- `001`：规则、围栏的三属性，历史记录保持 `LEGACY / UNASSIGNED / SCS`。
- `002`：告警、人员、设备、AI 事件、边缘节点/待处理事件、操作记录、摄像机、区域共九表添加 `project_id varchar(64)`、`region_id varchar(64)`、`subsystem_code varchar(32)`，均可空且无默认值。原数据保持原样；`ai_model` 是全局参考表，不机械增加区域列。
- `002` 另建空的 `scope_runtime_ownership`，主键为运行资源标识，包含明确的项目、区域、系统与归属依据。不得把代码中的演示编号、旧组织代码或设备名称当成真实归属依据。

`002` 在事务中持有九表短时排他锁，锁不可用即停止。重复执行会检查已有字段类型、长度、可空性和默认值；定义不一致时失败，由维护者核定，不自动改列或覆盖数据。已有运行归属表也须核对三个 CHECK 约束和 `created_at` 默认值；脚本会检查列定义及单列主键，但不会替换部署方已有约束。

完成后核对九表的 27 列、运行归属表、原行数和原主外键。应用账号至少需要对新增运行归属表的 `SELECT` 权限；维护该表的受限后台身份另按职责授权，不在本脚本中预设账号名。原业务表列级权限若存在，也应显式补齐所需列权限。服务需同时加载本版 `ScsCentralScope`、仓储范围查询与可信机器注册实现；仅执行 DDL 不等于完成接入。

未知/部分归属的历史数据保持隔离，不批量填入某个有效项目或区域。真实来源启用前，负责人须提供完整三属性、根对象 ID、可信机器来源与允许写入的对象清单；范围 WebSocket 只发送获权范围的刷新通知，不广播全量原始记录。

回退优先切回兼容应用并保留增量结构和新数据。已写入新归属后不要直接删列或删表；由维护者先核对依赖、导出必要数据，再制定单独回退操作。本源码交接补齐了通用脚本，不以此声称已在接收方环境执行。

构建前先在仓库根的 `IAM/context-client` 构建并安装当前 `context-client:2.1.0` 源码，确认其中含 `SharedDispatchClient`；不要复用缺该类的旧 JAR。随后在本模块 `backend` 执行 Maven 测试，在 `frontend` 使用锁文件安装依赖并执行 `typecheck`、`test:unit`、`build`。真实库迁移和业务验收由部署方按现有配置操作，不需要复制本次维护的私有运行记录。
