## 1. 我们为什么修改 SCS

原实现存在未验证 JWT 签名、接受伪造角色请求头、旧固定 Token 及只读子串判断等安全缺陷；另外原 SCS 前端不能携带有效身份，只能依赖未鉴权实例获得数据。目的：实现 **IAM 可信签票→SCS 一次性交换→HttpOnly 本地会话→服务端权限校验→IAM 注销联动**，并保留现有围栏、规则、告警等业务功能。

## 2. 本次交付改了什么

- 后端新增/调整 `JwtVerifier`、`ScsIamTicketValidator`、`ScsSsoController`、`ScsSessionRegistry`、`ScsSsoConfiguration`、`SecurityInterceptor` 等相关实现；不再信任客户端自报 `X-User-Roles`，拒绝 `alg:none`、旧固定票据、错误 issuer/audience/过期/签名；服务端执行只读写操作 403。
- 采用 **IAM 集中一次性验票**，SCS 通过服务身份调用 `verify-and-consume`，取得可信主体后建立本地会话；票据重放拒绝，撤销后关联 Cookie 失效。服务身份配置必须与 `aud=scs` 对应，不能硬编码共享凭据。
- 前端改为 `api/auth/session.ts` 提供换票流程，`credentials: 'include'` 使用同源 HttpOnly 会话，移除 `localStorage.scs_token`/静态 token，首次读取并及时从 URL 清除票据；后续业务请求不应反复携带一次性票据。
- 本轮补正了合法 audience 的解析、Spring bean 注册、失败响应 HTTP 语义、URL 票据残留与代理丢失必要服务端 Header 等实际问题。**不要从浏览器向业务 API 暴露 IAM 服务身份令牌**。
