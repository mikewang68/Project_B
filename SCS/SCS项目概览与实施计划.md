## 一、SCS 到底在做什么（业务定位与系统架构）

### 1.1 业务背景与使命
在大型铁路货场、港口集装箱多式联运及智慧物流枢纽中，装卸作业区（如门吊、翻箱机、正面吊、特种作业车、车辆通道及铁路线路股道）属于高危工业场景。人机交叉作业密集、视线盲区多、设备惯性大，极易发生机械挤压、碰撞、违规入侵及高处坠落等恶性人身伤亡事故。

**SCS（装卸作业安全卡控系统）**是整个智慧货场管控平台（Project_B）中承担**“现场人身安全红线保卫”**的核心子系统（S3）。系统通过物联网定位、计算机视觉、雷达测距、边缘智能计算与工业联锁技术，构建一套**“事前主动防范、事中秒级联锁、事后闭环溯源”**的立体化工业安全卡控网络。

### 1.2 业务铁律与核心设计原则
系统在设计之初确立了两条不可动摇的业务铁律与技术原则：

```
                    ┌─────────────────────────────────────────┐
                    │            SCS 核心业务铁律              │
                    └────────────────────┬────────────────────┘
                                         │
                 ┌───────────────────────┴───────────────────────┐
                 ▼                                               ▼
      【铁律一：纵深联锁卡控闭环】                    【铁律二：云边协同与极限自治】
  违规感知 ──> 秒级判定 ──> 声光报警             即使中心网络完全中断，EDGE 边缘网关
    │                           │               依据本地已同步的围栏与规则独立运行，
    └──> 联动 PLC/继电器切断动力 ┘               仍能执行毫秒级安全联锁，断网不瘫痪！
```

1. **纵深联锁卡控闭环**：
   违规判定不仅仅是“在屏幕上弹个报警”，而是能够根据风险等级，在毫秒级内向现场声光报警器、手环震动、直至现场 PLC/继电器发出停机信号，实现主动避险。
2. **云边协同与极限自治**：
   货场环境网络复杂，中心云与现场边缘可能发生断网。系统采用“云端统一策略编排与下发 + 边缘节点（EDGE-01 ～ EDGE-04）本地执行”架构。**当中心服务断开时，边缘节点依据本地已同步的围栏与规则独立运行，依然能够执行毫秒级安全联锁；网络恢复后自动补传事件并由云端闭环重放。**

### 1.3 七大核心业务领域
SCS 内部围绕装卸作业安全划分了清晰的七大业务领域：

```
                          ┌────────────────────────────────┐
                          │     SCS 安全卡控系统业务全景    │
                          └───────────────┬────────────────┘
                                          │
       ┌──────────────┬──────────────┬────┴─────────┬──────────────┬──────────────┐
       ▼              ▼              ▼              ▼              ▼              ▼
  [ 人员定位 ]   [ 电子围栏 ]   [ 设备防碰撞 ]   [ AI视觉识别 ]  [ 告警处置闭环 ] [ 规则引擎 ]
   Personnel       Fence        Collision         AI Event         Alert          Rule
       │              │              │              │              │              │
       └──────────────┴──────────────┼──────────────┴──────────────┴──────────────┘
                                     │
                     ┌───────────────┴───────────────┐
                     ▼                               ▼
               [ 运维与边缘自治 ]              [ 态势大屏/移动端 ]
                   Operations                  Screen / Mobile
```

1. **人员高精度定位（Personnel）**：
   对接现场 UWB 基站与防爆手环，实时获取作业人员三维平面坐标、电量、在线状态与定位质量；支持历史移动轨迹平滑回放与越界预警。
2. **电子围栏管理（Fence）**：
   支持在货场平面图上以**任意多边形（Polygon）**灵活绘制禁区、预警区、检修区与动态作业区；支持围栏“草稿 → 评审 → 发布 → 边缘同步”全生命周期管控，提供版本比对与差分下发。
3. **设备防碰撞监测（Collision）**：
   针对龙门吊（CRANE）、翻箱机（TIPPER）及装卸车辆，通过安装在设备上的测距雷达与定位标签，实时计算设备间距与相对速度；严格执行**“安全测距 → 减速预警 → 声光报警 → 联动停机 → 人工接管 → 风险解除”六级联动卡控流程**。
4. **AI 视频违规识别（AI Event）**：
   接入货场高空球机与作业面监控摄像头，实时识别未佩戴安全帽、未穿反光背心、翻越栅栏、非法穿越股道等违规行为，自动抓拍证据图片并转入人工复核流转。
5. **安全告警处置闭环（Alert - 核心主链）**：
   系统唯一的安全事件处置主链。无论来自人员越界、设备防撞还是 AI 识别的隐患，均汇总至告警中心，经历“触发建单 → 自动派单/人工认领 → 现场处置 → 等级升级 → 结案复核 → 证据归档”全生命周期，形成不可篡改的事件台账。
6. **安全规则配置引擎（Rule）**：
   提供低代码规则配置能力（如入侵判定阈值、碰撞安全距离、停机延时等），支持规则版本化管理、热更新发布与下发至边缘网关。
7. **态势投影与运维自治（Operations / Projection）**：
   提供中控安全大盘（Overview）、监控大屏（Screen）、移动巡检端（Mobile）以及针对边缘节点（EDGE-01 ～ EDGE-04）健康度与断网补传事件队列的运维监控。

### 1.4 系统技术基线与分层架构
- **后端架构**：
  - Java 17 + Spring Boot 3.5.5，采用松耦合的**模块化单体（Modular Monolith）**；
  - 核心构建工具：Maven 3.9.16（配置 Enforcer 规则强制对齐 JDK 与 Maven 版本）；
  - 实时通信：原生 Spring WebSocket（`/ws/live`），搭配 `LiveEventGate` 实现事务感知的事件广播；
  - 官方基础设施驱动：`org.opengauss:opengauss-jdbc:6.0.0`、RocketMQ 5.5.0 Client、Redis Starter（Kvrocks 协议适配）。
- **前端架构**：
  - Vue 3.5 + TypeScript（严格模式）+ Vite 7 + Pinia 3 + Element Plus 2.11 + ECharts 6.1；
  - 视觉规范：严格遵循企业级工业 SaaS 浅色风格（深海军蓝导航 `#24364A` + 浅灰蓝背景 `#F5F7FA` + 科技蓝 `#409EFF`）。

### 2.4 Phase B / B.5 关键架构缺陷与业务语义修复
在 2026-09-19 ～ 09-20 的架构审计专项中，针对阻碍落库与影响状态机流转的 5 项核心缺陷进行了代码级攻坚，全部闭环：
- **B5-01 告警升级生命周期死锁修复（RESOLVED）**：
  彻底解耦“业务处置状态（待认领/处置中/已结案）”与“风险等级（一般/严重/紧急）”。升级操作仅提升风险等级并记录 `previousRiskLevelCode`，不覆盖主状态，消除了状态流转死锁。
- **B5-02 防碰撞幽灵告警残留修复（RESOLVED）**：
  确立告警中心为唯一事实源，碰撞检测在触发告警前强制调用 `findOpenByDedupKey` 校验，告警关闭后立即重置设备对中的 `activeAlertId`，杜绝幽灵告警。
- **B5-03 实时事件门控嵌套重入机制（LiveEventGate - RESOLVED）**：
  重构为支持调用栈深度计数的 `Context` 上下文，在最外层事务退出时统一 flush 发送；任何内层抛出异常时标记失败并 discard 事件，确保事务完整性。
- **B5-04 生效规则编辑保护（RESOLVED）**：
  对处于 `ACTIVE` 状态的规则进行编辑时，系统不破坏正在边缘节点运行的活动规则，而是自动派生新版本草稿（如 `v2.4` → `v2.5`），待评审后重新发布。
- **B5-05 业务单号发号器冲突防范（RESOLVED / PARTIAL）**：
  消除了早期基于 `count() + 1` 产生的编号覆盖漏洞，单机环境下改为扫描最大数字后缀 `maxSeq + 1` 并循环探测；同时为 openGauss 数据库序列发号奠定了契约。

### 阶段一：openGauss 数据库实机验证与仓储层持久化（P0 优先级，即刻启动）
1. **实机 DDL 执行与兼容性验证（Compatibility Spike）**：
   - 在测试服务器（如 `node4` openGauss 实例）上建立 `safety` schema 并执行 `openGauss-schema-final-draft.sql`；
   - 检验 25 张表、21 个序列、字段类型、外键约束、唯一索引及注释在真实 openGauss 6.0 引擎下的创建情况。
2. **连接池连通与探针冒烟**：
   - 注入测试环境变量（`OPENGAUSS_HOST`, `OPENGAUSS_PASSWORD` 等），启动后端 `server` profile；
   - 验证 HikariCP 成功创建 10 个连接，验证 `/health/ready` 中 `database` 探针返回 `UP`。
3. **仓储层持久化重构（Repository Hardening）**：
   - 按照 `docs/pre-database-repository-hardening.md` 指南，逐步改造 9 个业务模块的 Repository（先从只读主数据、Rule、Fence 开始，再推进到 Alert 与 AiEvent）；
   - 将现有基于 `ConcurrentHashMap` 的 `InMemoryRepository` 切换为 Spring JDBC / MyBatis / JPA 真实数据访问层；
   - 消除现有内存仓储中的可变对象逃逸与深浅拷贝问题，在跨聚合写操作（如 AI 转告警、碰撞建单）上增加声明式事务注解 `@Transactional`。

### 阶段二：多实例治理与生产级中间件接入（P1 优先级）
1. **分布式发号与幂等持久化**：
   - 业务单号发号器（Alert, AI, Rule, Fence）切换至 openGauss `sys_business_number` 行锁或直接使用数据库 Sequence，替代当前 JVM 内存扫描；
   - 将内存单机 `IdempotencyService`（`ConcurrentHashMap`）迁移至 Kvrocks（Redis 协议），设置 24 小时 TTL 与原子防重操作，支撑多实例部署。
2. **事件总线解耦（Outbox + RocketMQ）**：
   - 将 `DomainLivePublisher` 的直接内存广播，演进为**“事务本地事务表（Outbox）+ RocketMQ 事件广播”**，防止单点推送阻塞或丢消息。
3. **Demo 端点与生产环境彻底隔离**：
   - 针对当前无条件执行的 3 个 Seeder（`DemoSeedInitializer` 等）以及 10 多个 `simulate*` 端点（如碰撞模拟、入侵模拟），增加 `@Profile("dev")` 或 `@ConditionalOnProperty` 防护注解，确保在 `server` 生产环境下绝不暴露演示入口，杜绝污染生产数据库。

### 阶段三：边缘网关协同与现场真实硬件对接（P2 优先级）
1. **真实硬件协议接入与适配（Device Adapters）**：
   - 对接收集现场 UWB 定位基站/手环、毫米波测距雷达、AI 高空球机及现场 PLC 控制箱的真实厂商通讯协议（Modbus TCP / MQTT / HTTP / 私有二进制包）；
   - 开发设备适配层，实现硬件报文解析与平台标准事件转化。
2. **边缘节点自治协议实测**：
   - 在现场真实边缘计算网关（EDGE-01 ～ EDGE-04）部署边缘引擎，联调围栏 Polygon 顶点同步与规则下发协议；
   - 实测在拔掉网线/网络风暴等极端工况下，边缘侧对越界与碰撞危险的本地毫秒级停机联锁能力，验证网络恢复后的事件补传与状态回正。
3. **全链路卡控时延压测**：
   - 搭建真实传感器测试环境，压测“紧急规则触发到设备切断动力 ≤ 2 秒，普通告警推送 ≤ 5 秒”的关键业务合规指标。

### 阶段四：生产级拓扑部署与三节点联调（P2 优先级）
1. **部署配置模板落地**：
   - 待运维网络拓扑到位后，替换 `deploy/nginx/` 与 `deploy/easegress/` 下的所有环境变量占位符（`__NODE4_BACKEND_HOST__` 等）；
2. **自动化发布流水线跑通**：
   - 在服务器上运行 `build-server.sh` 脚本执行严格环境校验与构建；
   - 通过 `verify-deployment.sh` 批量检验三节点反代链路与健康端点状态；
3. **可观测性监控接入**：
   - 配合 Categraf 抓取后端 `/actuator/prometheus` 指标，配置 JVM 堆内存、HikariCP 活跃连接数、WebSocket 连接数及告警吞吐量大屏。
