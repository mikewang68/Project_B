# 阶段 8：数据迁移、联调和部署实施与验收记录

## 1. 交付结果

阶段 8 已完成本地可交付基线。项目仍是一个 Spring Boot 单 JAR，前端产物随 JAR 发布，openGauss 由 Docker Compose 提供。

新增能力：

- 旧 MySQL/SQLite 预检、迁移、幂等重跑和审计工具。
- 15 张核心旧表到新业务模型的字段及状态映射。
- 其余旧业务表原文归档；密码、密钥和令牌字段在归档前脱敏。
- openGauss SQL 备份、SHA-256 校验和恢复脚本。
- 登录、工作台、库存、入库、出库、财务、集成和奇门回环冒烟测试。
- 可配置请求数、并发数和 P95 阈值的性能冒烟测试。

## 2. 数据迁移范围

直接迁入新业务表的旧表包括：

| 旧表 | 新表/能力 |
|---|---|
| `w_warehouse` | `wms_warehouse` |
| `u_partner` | `wms_owner`、`wms_partner` |
| `w_area`、`w_workarea`、`w_location` | 库区、工作区、库位 |
| `inv_category`、`inv_good` | 货类、货品 |
| `inv`、`inv_rfid` | 库存余额、RFID/唯一码 |
| `i_stockin`、`i_stockin_line` | 入库单及明细 |
| `o_stockout`、`o_stockout_line` | 出库单及明细 |
| `f_money_account`、`f_money` | 财务账户、费用单 |

旧拆装、分配、箱单、旧流水、配置等无法与新领域模型一一对应的数据写入 `legacy_archive_record`，保留来源表、来源主键及脱敏后的 JSON 原文。迁移运行写入 `legacy_migration_run`。

旧用户密码不导入新认证体系。新系统继续使用 BCrypt 和首次改密机制；生产切换时由管理员创建账号或触发统一重置。

- `mt-wms-demo/.demo-data/auth.sqlite3`：公司和用户数据。
- 两个文件均以只读模式打开，`quick_check` 为 `ok`。
- 合并来源指纹：`25676fb8384072ecc9061a5b429f56dafc134b431a92663920d3fb943e9fc2e5`。

| 合作伙伴 | 14 |
| 库区 / 工作区 / 库位 | 11 / 10 / 40 |
| 货类 / 货品 | 10 / 34 |

旧库重复的 `default` 仓库、货主、货类和 `PICK/QC/STAGE/ZERO` 等库位已按业务唯一键合并；重复的 `monitor` 用户合并为一个账号。目标库复核未发现仓库、货主、货品、入库单或出库单重复业务键。

库存合计为可用 `7007`、分配 `0`、冻结 `71`。出库明细合计为计划 `3171`、分配 `1892`、拣货 `1496`、发运 `1095`，均与 SQLite 一致。财务按收入/支出和各状态汇总后的金额、实收实付与旧库一致。

旧用户密码不直接复制。新建的演示用户使用本地初始密码并强制首次改密；已经修改过密码的现有 `admin` 账号保持原密码不变。角色映射结果为：`admin/admin0` 管理员，`monitor/demo_manager` 仓储管理员，其余演示岗位普通用户。

## 4. 工具与部署验收

- V012、V013 已在 openGauss 6.0.5 执行并登记。
- 先使用隔离 MySQL 5.7 样例库完成 15 表预检和迁移，再使用真实 SQLite 双库完成切换。
- 真实 SQLite 重复执行后，目标核心表、明细表和历史归档数量保持不变。
- Python 迁移转换、SQLite 双库适配及敏感字段脱敏测试 5 项通过。
- 生成 openGauss 完整 SQL 备份及 SHA-256 文件，并执行两次恢复演练。
- 每次恢复后 V001–V013 校验通过，应用能够重新启动。
- 九项业务冒烟全部成功。
- 性能冒烟：300 请求、并发 12，成功 300、失败 0；平均 2.92 ms，P95 3.27 ms，最大 44.85 ms。该结果仅代表本机存活端点基线，不替代生产容量测试。

## 5. 当前限制

旧盘点、移库、调整和库存流水与新领域模型不能逐行等价转换，已脱敏保存在 `legacy_archive_record`，核心余额和业务单据则进入新业务表。若生产环境还存在比 `.demo-data` 更新的数据库，应重新按运行手册执行并由业务人员签字确认。

第三方奇门真实账号、公网回调、生产域名、TLS 证书和服务器资源不属于本地验收数据，部署时需由实际环境提供。
