# 阶段 4：库存

状态：已完成  
完成日期：2026-08-20

## 旧系统行为保留

- 库存按当前公司、仓库、货主、库位、货品、批次、质量、供应商和 LPN 维度隔离。
- 冻结将可用量转为冻结量，解冻执行反向转换，库存总量不变。
- 移库只能使用可用量，且出库位与入库位在同一事务中更新。
- 调整和盘点不允许使可用量变成负数。
- 库位补货保留“告警数量 + 补齐数量”规则，并从其他库位按可用量由高到低补货。
- RFID/唯一标签编码在公司范围唯一，标签数量不能超过所属库存。

## 新库存模型

- `inv_balance`：当前余额，显式区分可用、已分配和冻结数量，带版本号。
- `inv_transaction`：不可变库存流水，记录总量、可用量和冻结量的前值、变动和后值。
- `inv_operation` / `inv_operation_line`：调整、冻结、解冻、移库、盘点和补货的单据头与明细。
- `inv_serial`：RFID/唯一标签台账。
- `inv_replenishment_rule`：货品与目标库位的自动补货阈值。

## 一致性与幂等

- 写操作对目标库存行执行 `FOR UPDATE`，新余额同时受数据库非负约束保护。
- 库存余额、业务单据和流水使用同一 Spring 事务；移库和补货不会产生半完成状态。
- 调整、移库、冻结、解冻、盘点和补货都校验幂等键；重复请求返回 400 且不重复入账。
- openGauss 当前兼容模式会将空字符串视为 `NULL`，因此无批次/供应商/LPN 维度统一使用 `-` 占位。

## 接口与页面

- `/api/v1/inventory/balances|transactions|warnings|serials`：台账查询。
- `/api/v1/inventory/adjustments|moves|freeze|unfreeze|counts`：核心库存操作。
- `/api/v1/inventory/replenishment-rules`：补货规则查询和维护。
- `/api/v1/inventory/replenishments/generate`：自动补货移库。
- 库存中心提供库存余额、操作流水、库存预警、补货规则和唯一标签五个标签页。

## 数据库迁移
