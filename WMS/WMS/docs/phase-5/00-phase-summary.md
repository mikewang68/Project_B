# 阶段 5：入库

状态：已完成  
完成日期：2026-08-20

## 旧系统行为保留

- 入库单支持多货品明细和分次收货，全部收完自动完成。
- 保留采购、退货、调拨、寄售、生产、借用归还等旧入库类型。
- 支持无单快捷入库、按货品编码/条码扫码收货和 RFID/唯一标签登记。
- 未收完入库单可强制完成；取消只关闭未收部分，已收库存保留。
- 库位推荐优先级为货品默认库位、相同货品已有库存、收货暂存位、其他可用库位。

## 数据模型与状态

- `stockin_order`：入库单头，保存业务单号、外部单号、类型、来源、伙伴和幂等键。
- `stockin_order_line`：入库明细，保存计划量、已收量、批次、质量、供应商、生产/失效日期和单价。
- `stockin_receipt`：每次收货记录，关联库存操作、库位、数量、LPN 和标签数。
- 状态统一为 `DRAFT → RECEIVING → COMPLETED`，未完成单据可转为 `CANCELLED`。
- 入库业务单号使用 `R`，收货操作号使用 `IR`。

## 一致性与幂等

- 入库单、收货记录、库存余额、库存操作和库存流水在同一 Spring 事务中提交。
- 收货使用 `FOR UPDATE` 锁定入库单、明细和库存余额，默认拒绝超收。
- 创建、收货和快捷入库使用幂等键；重复请求返回 400 且不重复入账。
- 外部入库单号在当前公司、仓库和货主下去重。
- RFID/唯一标签在公司范围唯一，同一请求内也会检查重复。

## 接口与页面

- `GET/POST /api/v1/stockin`：入库单列表和创建。
- `GET /api/v1/stockin/{id}` 与 `/{id}/receipts`：单据明细和收货历史。
- `POST /api/v1/stockin/{id}/receipts|scan`：按明细或条码收货。
- `POST /api/v1/stockin/{id}/complete|cancel`：强制完成和取消。
- `POST /api/v1/stockin/quick`：快捷入库。
- `GET /api/v1/stockin/location-suggestions`：入库库位推荐。
- 入库管理页面提供汇总、多明细建单、详情、收货历史、RFID 录入、快捷入库和单据关闭操作。
