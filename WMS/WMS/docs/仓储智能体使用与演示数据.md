# 仓储智能体与货运演示数据

## 功能入口

登录 WMS 后进入“仓储智能体”（`/#/agent`），包含智能查货、定时巡检、站内预警、库位利用率四个标签页。顶部“站内预警”直接打开预警标签页。既有主题颜色、导航布局及原业务页面保持可用。

- 查货：日常语言描述日期、材质、外形、供应商等线索，模型调用只读业务工具，展示实际收货时间、批次、数量、库位及匹配理由。相关度不是概率；最多返回 20 个候选，大范围查询提示补充线索。结果表格默认展开，直接来自数据库；模型文字解读可能引用错误，单号和数量等必须以表格核对，无成功查询时不展示未经核实的业务断言。
- 巡检：按北京时间每天固定时间或每隔若干分钟检查库存。低库存、补货、冻结、承重和数据缺失由确定性规则计算，不依赖模型可用。任务、告警与快照持久化，关闭浏览器后继续执行。
- 通知：站内提醒归任务创建人；风险去重、恢复跟踪、重复提醒间隔可配置。邮件是可选通道，默认关闭，不发送测试或真实邮件。
- 分析：系统暂存库位不计入占用率；承重按可用、分配、冻结库存总量计算。钢材单位为捆时填写 kg/捆，散货单位为吨时按 1000kg/吨换算，不重复乘单位重量。缺失重量/容量时不伪造百分比；当前不提供空间体积利用率。

权限：`agent:read` + 库存读权限可查询，`agent:manage` 可配置巡检，基础资料写权限可维护单位重量。租户范围来自服务器会话，模型不能切换公司/仓库/货主，也没有 SQL、shell、自动修改库存或发送邮件工具。

## 模型与邮件配置

应用服务器通过受控网络访问支持 Chat Completions / tools 的模型接口，以下变量置于私密运行配置，不提交到 Git：

```ini
WMS_AGENT_ENABLED=true
WMS_AGENT_BASE_URL=<模型的/v1入口>
WMS_AGENT_API_KEY=<密钥>
WMS_AGENT_MODEL=<模型名>
WMS_AGENT_TIMEOUT_SECONDS=30
WMS_MAIL_ENABLED=false
```

如以后需要邮件，确认发件和授权的收件地址后，配置 `WMS_SMTP_HOST`、`WMS_SMTP_PORT`、`WMS_SMTP_USERNAME`、`WMS_SMTP_PASSWORD`、`WMS_MAIL_FROM`、TLS 参数，并显式设置 `WMS_MAIL_ENABLED=true`。465 使用 SSL，587 通常使用 STARTTLS，按邮箱服务商要求选择；不要关闭 TLS 证书主机名校验。巡检任务里另外填写收件邮箱，最多 5 个。

邮件持久队列最多自动尝试 5 次，之后可以手动重试；极少数 SMTP 超时场景可能重复投递。页面“已配置”不代表实际投递成功。关闭开关时停止发送，未发送队列不会被删除，以后重新启用前应检查积压邮件。

模型请求有超时、并发限制、失败熔断及规则降级。模型输出只作为文本展示；业务工具重新验证权限。定时巡检重新检查任务创建人的账号和授权。数据库不可用、邮件或模型失败不会改写原库存业务数据。

新增工具时同时补定义、执行白名单、权限校验、前端展示和隔离测试；新增规则复用稳定风险键与去重机制。新增数据库变更另写下一版本迁移，不修改已经应用的 V014。

## 导入货运演示数据

数据定义：`database/demo/freight-demo.json`。只用于隔离的开发/演示数据库，不用于真实运输、承重或价格判断。

包含 10 种货品（5 种钢材、2 级粉煤灰、矿渣粉、水泥、碎石）、5 家供应商、2 家客户、2 家承运商、15 笔收货、11 个库位及冻结/补货示例。企业名带“演示”标记，电话不填真实号码。所有新增业务记录都有 `DEMO-FREIGHT-20261007` 标记；保留旧业务记录。

使用 PowerShell 7，设置私密 `WMS_COMPANY`、`WMS_USERNAME`、`WMS_PASSWORD` 环境变量，或传入本机私密 env 文件。账号需要相应基础资料、入库、库存写权限。

```powershell
pwsh -File scripts/seed-freight-demo.ps1 -BaseUrl https://your-wms-host:port -CredentialFile C:/private/wms-login.env -CaCert C:/private/lab-ca.crt
```

必要时 `-ResolveHost 'your-wms-host:port:server-ip'` 定向解析。不开启 `-k`，不关闭证书链或主机名验证；Windows 下实验室私有 CA 的不可达吊销信息仅采用 best-effort 检查。环境文件示例只需三个登录字段，不能提交真实文件。

脚本通过真实业务 API 创建资料、收货及库存流水，已完成的同标记收货会跳过，不重复增加库存。资料编码与非演示数据碰撞、入库单部分完成或单位已被改动时停止，不覆盖或删掉他人数据。运行前备份数据库；失败后已提交的前序业务事务可能保留，核查后可以重跑。

普通 API 导入的收货时间是真实导入时间。如果需要复现“前天那批货”的历史演示，管理员在确认仅影响演示记录后，可手动执行 `database/demo/freight-demo-history-20261007.sql`。SQL 固定模拟 2026-10-01～07 的时间，严格匹配默认公司/仓库/货主、种子键及演示标记，要求恰好 15 条，并在一个事务中同步收货、单据、操作及库存流水时间。它不是生产迁移，不在日常启动中自动执行；后续日期请用明确日期查询，不会每天把历史数据重新变成“前天”。

## 演示与验证

建议问题：

- “找 2026 年 10 月 5 日前后到的钢材，名称记不清了。”
- “昨天到的一批灰料，是粉煤灰吗？展示供应商和批次。”（历史种子参考日是 2026-10-07）
- “分析钢材区的承重情况，说明缺失数据和风险。”

参考场景：`FD-S02` 承重约 94.09%，`FD-S04` 约 111.11%（人为超载演示，不用于真实作业），`FD-EMPTY` 空闲；`FD-REBAR20` 和二级粉煤灰低于安全库存，冷轧钢板有 2 捆冻结库存。

```bash
mvn clean verify
```

构建同时检查前端类型、单元测试、生产打包及后端测试。线上可用 `scripts/verify-freight-agent.ps1` 进行真实查询、巡检去重与利用率验收（该脚本会保存查询记录、预警与快照，不是只读探针）。邮件保持关闭，邮件投递不是本次验收范围。

先测试构建再替换运行 JAR、健康检查，失败回退旧 JAR。V014 仅增加表/权限，通常可保留新表回退代码；不要为了回退页面直接覆盖整库，从而丢失上线后的业务数据。备份、产物、密钥和运行日志都不属于源码提交内容。
