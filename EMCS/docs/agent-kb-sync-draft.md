## 一、PRD 增补建议稿（页面级）

### 新增能力：AI 智能助手（问数 + 巡检）

**能力定位**：在五幕演示主线之上叠加 AI 层，将系统已有数据能力（能耗、告警、质量、成本、建议）通过大模型转化为自然语言交互与自动化诊断。差异化卖点的二次放大器：AI 回答/报告主动引用重算版本差异、质量着色、建议闭环三档等既有卖点。

**页面 1：智能问数对话面板（全局悬浮）**
- 入口：全站右下角 AI 悬浮球，任意页面可唤起右侧抽屉（约 400px），不打断当前页面
- 交互：自然语言提问 → 逐条展示工具调用过程条（"正在查询A区能耗…"）→ 流式回答
- 回答规范：结论先行、引用具体数字、关键实体带跳转（溯源到对应页面）
- **定位文案规则：禁止内部编号外显**，一律"区域 → 设备 → 计量对象 + 触发时间"业务名称链
- 会话：保留最近 10 轮上下文，不落库
- 降级：模型服务不可用时显示"AI 助手暂时不可用"，不影响主线功能

**页面 2：AI 巡检报告页（侧边栏新菜单）**
- 触发：每日 07:00 定时 + 页内"立即巡检"手动按钮
- 巡检范围：2 装卸区 / 12 设备 / 48 计量点近 7 日：数据质量（缺数/补传）→ 告警积压 → 能耗/成本环比 → 设备级异常
- 报告结构：摘要 + 统计卡（检查项/高危/中危/完整率）+ 发现项列表（severity 着色、证据、建议、跳转链接）
- 发现项与 INJ-01–08 注入异常呼应；定位文案规则同上
- 权限：菜单对 energy_mgr / admin 可见（K.6 窄授权口径）

**账号数据范围**：AI 工具层固定使用 energy_mgr 等价只读视角，不随登录账号变化（demo 简化，正式版需按账号数据范围过滤——列入正式版差异说明）。

## 二、技术选型增补（《demo-技术选型与开源借鉴》）

| 项 | 选择 | 许可证 | 借鉴纪律 |
|---|---|---|---|
| agent 框架 | AgentScope 2.0（阿里） | Apache-2.0 | 作为 pip 依赖使用，非二次开发；网上 1.x 教程过时，以官方 2.0 文档为准 |
| 模型接入 | OpenAI 兼容接口（服务器自部署大模型 / 开发期本机 Ollama） | — | API key 只存 .env，不入库 |
| 模型 | Qwen3 系列（以实际部署为准） | 开源可商用 | function calling 为硬性要求 |

选型理由摘要：①国产框架+国产模型+私有化部署的自主可控叙事；②FunctionTool 从 docstring 自动生成工具 Schema（已实测中文解析正常）；③内置权限钩子/MCP 支持，留有对接客户其他系统的标准出口；④备选 LangGraph（MIT，全球生态最大）落选原因：中文生态与 Qwen 配套弱于 AgentScope，且无 Java 版（B 项目其他子系统若为 Java 技术栈,AgentScope-Java 可复用同一框架心智）。

关键架构决策（防重议）：
- **工具路线而非 text-to-SQL**：模型只做"选工具+填参数"（枚举锁死），SQL 全部人写。对齐业界 ChatBI 实践（语义层思想）
- **问数=ReAct agent，巡检=固定 workflow**："能 workflow 不 agent"
- 全部工具只读；巡检报告表是 AI 链路唯一写入点

## 三、需求基线新增条目建议（编号待知识库分配）

1. AI 问数对话面板（全局悬浮、过程可视化、流式回答、溯源跳转）
2. AI 回答与报告的业务名称定位规范（禁止编号外显）
3. AI 自主巡检（定时+手动、四类检查、结构化报告落库）
4. AI 巡检报告页（列表/详情/severity 着色/跳转）
5. AI 服务降级策略（模型不可用不影响主线）
6. AI 演示回归问题集（≥15 问，演示前必须全绿）——对应坑点纪律
