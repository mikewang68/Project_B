7 项真实组件检查全部通过。原开发应用恢复后仍有 29 条事件，逐条核对原文、摘要、CID、版本、交易标识及存证状态，均与演练前一致。本轮沿用 2026-09-14 发布的应用制品，没有修改业务代码、数据库结构或合约。

## 验收方式与隔离范围

在专用开发环境暂停原应用写入，取得同一静止检查点的数据库、应用暂存和 IPFS 冷仓库备份。数据库恢复到新建隔离库，应用使用独立目录，IPFS 恢复副本仍在原 IPFS 独立节点。副本临时使用原 IPFS 回环端口，期间原 IPFS 停止；未增加跨机放行端口。

Fabric 保持运行并使用原账本。故障测试新增两条明确标记的模拟事件，产生真实链交易；隔离库、证据副本、暂存、原始导出包及日志保留以供复核。原开发库没有导入这两条测试记录。

## 随验收修正的部署问题

- IPFS 启动脚本现在等待 RPC 就绪并核对仓库路径，最多等待 30 秒，避免进程刚启动就误报就绪。
- Kubo 0.43.0 的离线运行仍可能读取远程 AutoConf。配置工具关闭 AutoConf 并清理相关自动配置项，先保存权限为 600 的旧配置；原仓库及恢复副本已验证可启动。
- IPFS 备份脚本只在备份前服务运行时恢复启动，恢复后检查就绪。
- 数据库恢复工具使用服务器私有配置进行非交互认证并关闭标准输入，避免等待密码输入；超时错误不回显含凭据的完整命令。

尚未配置开机自动启动或进程守护；机器重启后的自动恢复仍需补充。文件缺失下载目前返回通用 HTTP 500，核验可显示失败项且导出被拒绝，后续应细化下载错误分类。

## 复现与证据保存

先按模块 README 配好四节点环境，确认使用专用开发实例且没有待办任务。演练会临时停止本工程原应用和 IPFS，并向开发账本增加两条模拟交易；不要同时运行两组演练。每次从 prepare 创建新标识，不对已完成的一组重复 exercise。

在模块根目录执行：

```powershell
.\scripts\sync.ps1 -Roles application,ipfs,database
python tests/recovery/run.py prepare
python tests/recovery/run.py exercise
```

协调器在结束或异常时尝试恢复原服务。如果本机被关闭或协调器被强制终止，使用保留的当前演练标识恢复：

```powershell
python tests/recovery/run.py restore-live
python scripts/check-environment.py
```

本机详细输出位于 `.local/test-results/<演练标识>/`，服务器资料位于工程的 `runtime/recovery/<演练标识>/`。同组备份及摘要清单集中保存在应用节点，节点原件也保留。详细 JSON、证书、原始 ZIP 和运行日志不进入公开仓库；不会通过重制证据包或修改摘要脱敏。
