# 单层 HTTP 入口修正 · 2026-09-16

状态：管理员已完成单层迁移，开发电脑到网关的实际 HTTP、浏览器页面及后端来源限制检查通过。入口已可用。

## 迁移前的环境与故障

- 网关已有系统 Nginx 1.24.0；RPM 和 DNF 记录显示该软件包于本次管理员操作安装。检查时未运行，80 端口空闲，系统 conf.d 为空。旧 Easegress 和静态 Web 服务也处于停用状态。
- 应用节点原有系统 Nginx 正常承载其他站点；旧方案新增的项目接入单元反复重启失败。当时 TRUST Java 应用只监听回环并返回 UP。
- 两台机器报错均为无法写入用户目录下的日志或 PID。目录属主为部署账号，SELinux 处于 Enforcing；非特权回环预演与 systemd 启动上下文不同。尚未取得管理员 AVC 审计，不能把某条 SELinux 拒绝规则作为已证实的唯一原因。
- 原工具只检查瞬时 active 状态，未验证稳定 HTTP 响应，误报了应用侧启用成功。

## 修正

1. 网关复用系统 nginx.service，仅新增 conf.d 配置，使用标准日志、缓存和 PID 路径。系统 Nginx 对上游联网的 SELinux 布尔值已开启。工具不再次安装软件，不关闭 SELinux。
2. 应用节点撤掉项目新增代理，由现有 Java 直接监听 IPv4 28182。防火墙只放行网关来源；回环入口保留。原有其他 Nginx 站点不在修改范围。
3. 新脚本识别旧状态并核对摘要后清理，迁移失败尝试回退到回环应用。移除来源规则前先恢复回环监听。
4. 两侧要求同一进程连续三次返回 HTTP UP；应用侧检查 Java PID 与监听端口。实际检查失败返回非零退出码，不打印应用成功。

## 验证

本地 12 项配置、旧服务清理、回退顺序和就绪判定测试通过；原 8 项部署配置及源码打包测试通过。包含“服务显示 active 但 HTTP 拒绝连接”和“进程反复更换 PID”两个误报回归场景。

应用节点 Linux 上同样通过 12 项测试，应用启停脚本通过 Bash 语法检查。真实单层 Nginx 回环预演通过 6 项：直连 Java 健康、页面、登录与 CSRF/台账、伪造转发头不能绕过来源限制、2 MiB 请求到达应用校验、22 MiB 请求被拒绝。原事件数量保持 29，预演进程退出。详细材料写入 Git 排除的 `.local/test-results/http-access/`，不公开机器地址和运行日志。

## 正式迁移后验证

- 网关 nginx.service 为 active/running，已启用自启，检查时 NRestarts 为 0。应用与网关原有的项目代理单元均为 not-found，旧故障代理已清理。
- 应用 IPv4 28182 端口属于本项目 Java 进程；回环与内网健康均通过。应用节点原有系统 Nginx 的主进程未更换，保持运行。
- 开发电脑直接通过网关 HTTP 入口完成健康、页面资源、实际登录与 CSRF、台账和任务查询。数据库、IPFS、Fabric 均为 UP，业务事件仍为 29 条。
- 无界面 Chrome 通过真实 HTTP 入口完成 8 项页面检查：登录、台账、详情与证据核验、批次溯源、录入/导入页、补办任务、运行状态和移动端宽度。没有模拟 API，没有新增业务事件或附件，没有页面脚本错误。
- 从非网关组件节点发起连接，应用主机 SSH 可达，但 28182 被拒绝；网关实际转发成功。这验证了后端来源限制。

证据保存在维护者本机 `.local/test-results/http-access/`：`online-check.json`、`gateway-service.json`、`application-service.json`、`backend-source-rejection.json` 及 `browser/ui-real.json`、页面截图。页面测试支持 `TRUST_BASE_URL` 指定真实入口。
