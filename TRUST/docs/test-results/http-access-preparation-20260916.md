# HTTP 网关配置准备与回环预演 · 2026-09-16

> 历史记录，方案已被替代。当天随后正式启用时，网关检查失败，应用接入反复重启。此处普通账号回环预演不覆盖正式 systemd 权限，不能作为上线依据。当前方案与状态见 [单层入口修正记录](http-access-correction-20260916.md)。

配置准备及预演通过，正式网关尚未启用。目标链路为浏览器访问独立网关，再通过内网 HTTP 到应用节点的独立接入进程，最后到原 TRUST 回环服务。网页链路不使用 SSH 隧道。

## 已核实与已完成

- 网关拟使用的 80 端口空闲，应用仍监听本机 28182。应用节点现有其他网站占用 80，本方案使用独立配置及服务，不修改该网站。
- 两台机器使用 openEuler 24.03 LTS-SP3，防火墙运行中；网关未安装 Nginx，应用节点的 Nginx 为 1.24.0 发行版包。
- 已准备私有地址与允许来源配置、两侧 Nginx 配置、专属 systemd 单元、管理员启用/回退工具及启用后的只读检查工具。
- 原有 8 项部署配置测试通过；新增 7 项访问配置及回退测试在 Linux 上全部通过，包括拒绝非法地址/过宽网段、组件隔离、回退只删除本次新增规则、管理文件被改写时拒绝回退。
- 两份 systemd 单元通过系统工具校验。

## 真实回环预演

使用应用节点已安装的真实 Nginx 启动两个临时回环监听，连接原 TRUST 应用及真实数据库/IPFS/Fabric。6 项检查通过：

| 检查 | 结果 |
|---|---|
| 双代理健康检查 | 两个 Nginx 进程均可转发应用健康请求。 |
| 页面 | 可以经双代理取得已构建的前端页面。 |
| 登录与查询 | 真实账号登录、CSRF、事件台账和三个组件状态正常。 |
| 来源限制 | 两个监听均拒绝非授权 TCP 来源；伪造 X-Forwarded-For、X-Real-IP 和 Forwarded 头不能绕过限制。 |
| 大于 1 MiB 的请求 | 2 MiB 无效内容请求到达应用校验并被拒绝，没有新增业务事件。 |
| 超出上限的请求 | 声明超过 21 MiB 的请求在入口返回 413。 |

原有事件数量保持 29。预演进程结束后停止，真实业务服务未重启。详细日志、配置计划及预演 JSON 保存在服务器 `runtime/http-access/` 和维护者本机 `.local/test-results/http-access/`。

Nginx 的配置测试会尝试绑定监听地址，不能在应用节点验证属于另一台机器的正式地址。此次回环配置完成了真实语法及转发验证；正式网关地址和 80 端口由管理员启用时在网关本机检查。管理员工具使用短暂的受限系统任务完成 80 端口配置检查。

## 尚待完成

两台服务器均未开放免密 sudo，因此正式安装、系统服务及防火墙规则尚未应用。仍需管理员按 [HTTP 部署说明](../http-access.md) 先启用应用接入、再启用网关，并完成真实跨机 HTTP、浏览器操作、来源拒绝和服务重启检查。当前不宣称正式入口已可用，也不把 HTTP 单元的重启能力解释为四个原业务组件的开机自动恢复。
