# 应用导航准备验证

日期：2026-09-16。状态：代码、配置与预演已完成；正式 80 端口首页尚待网关管理员更新。不能将本记录视为正式导航上线验收。

## 改动与已核实入口

复用既有网关系统 Nginx，在 `/` 提供静态中文应用导航，TRUST 从 `/trust/` 进入，保留原根路径 API 和静态资源转发。其余应用使用原内网地址直链，不新增代理、不改各业务服务。

开发环境清单含 TRUST、生产调度、设备健康、两套现有仓储部署、安全卡控、身份权限、系统设置、Nightingale 与 Cockpit，共 10 项。两套仓储分别标为 MT-WMS 和独立实例，不推断其主次。生产调度、身份权限与设置标注模拟演示；设备健康标注数据库联调。DTS、EMCS 未核实已发布页面，本轮不生成入口。数据库、存储及其他非网页端口不列入导航。

开发电脑已确认可直接访问应用节点现有业务端口。HTTPS 入口保留原证书与协议，没有降级 HTTP、安装根证书或修改业务登录。现有入口可发现不等于其完整业务流程已验收；仅具备网关 VPN 访问、没有应用节点内网路由的电脑仍不能保证访问这些直链。

## 正式切换与后续核验

已同步网关源码和私有入口清单。管理员在网关工程目录执行 `sudo python3 deploy/http-access-admin.py update --role gateway`；脚本核对旧配置，备份后测试并重载，逐项核验新首页、静态资源、TRUST 入口及原健康接口。应用节点不需管理员操作。

完成后从开发电脑运行 `python scripts/check-http-access.py`，并将 `TRUST_PORTAL_URL`、`TRUST_BASE_URL` 指向正式首页和 `/trust/`，运行导航与 TRUST 浏览器回归，再记录实际上线状态。当前障碍是网关 sudo 需要交互输入密码。
