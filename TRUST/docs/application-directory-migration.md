## 执行顺序

1. 管理员确认目标不存在，创建 `/data/app/trust`，所有者为 `trustdev:trustdev`，目录权限为 0755。
2. 保留原路径为指向 `/data/app/trust` 的兼容符号链接，现有同步和备份工具通过旧路径访问新实例。网关、数据库、IPFS、Fabric 保持原目录，共用 `remoteRoot` 不变。
3. 在停机前复制制品和代码，核对摘要；记录现有健康状态、事件数量、任务状态和证据文件清单。
4. 停止旧实例，最终复制运行数据并校验，修正新实例路径配置，确保没有同时运行两个处理进程。
5. 从新目录启动原制品，核对进程工作目录、28182 健康、登录、台账、任务、三组件状态和证据读取。目录迁移与应用版本升级分开验收。
6. 原目录保留作回退备份；后续同步和管理工具只指向新实例。数据库、IPFS 数据和 Fabric 账本不移动。

## 回退

新实例启动或核验失败时，先停止新实例，确认 28182 无重复进程，再从保留的原目录启动旧实例。若新实例已接收业务写入，先核对并同步新增证据暂存文件，不能直接用迁移前文件覆盖新数据。
