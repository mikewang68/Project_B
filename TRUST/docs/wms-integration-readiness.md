# WMS 接入准备评估

评估日期：2026-09-16。依据为当前仓库 WMS 源码，只读检查未修改 WMS。TRUST 的通用接收、归档、上链、补办和核验已具备开发联调基础；WMS 可从收货和实际发运开始接入，正式联调前需补齐来源事件快照与批次关联。

尚未确认运行中的 WMS 版本与本仓库源码一致。部署说明和源码存在不构成已上线证据；联调入口、运行版本、测试账号与数据范围应在接入前核实。

## 已有依据与缺口

| 对象 | 源码事实 | 接入影响 |
|---|---|---|
| 收货 | `GET /api/v1/stockin/{orderId}/receipts` 返回记录 ID、作业号、货品、库位、数量、批次、质量类型、LPN、操作人名称和时间。底表另存公司、仓库、货主、明细、库存余额、供应商和操作人 ID。 | 可建议映射为 `WAREHOUSE_IN`，还需补单位、稳定操作人身份与归属快照；不能由一条收货记录推定独立的到货、检验、过磅均已发生。 |
| 发运 | `GET /api/v1/stockout/{orderId}/events` 的 EventView 未返回 `allocationId`、`batchCode` 或单位；底表已有 `allocation_id`，SHIP 写入时记录到具体分配。分配查询可关联库存批次。 | 需将实际发运事件关联到具体分配和批次，并固化发生时的数量、单位；不可用订单默认批次推测每次发运来源。 |
| 归属 | 收货与发运查询均按公司、仓库、货主范围过滤。 | 应明确映射到 TRUST 组织范围和来源命名空间，服务端约束发送账号权限，保留原业务编码。 |
| 操作身份和名称 | 底表有操作人 ID，查询结果中的名称来自当前用户及主数据关联。 | 采用稳定身份标识，事件发生时固化需要的显示信息；避免日后名称变化导致同一来源事件内容冲突。 |
| 容器与单据 | LPN 是物流容器标识，operationCode 是作业号。 | 保留原语义；钢材捆号、真实交接单号需独立业务依据，不能直接等同。 |
| 证据 | 收货质量类型存在，但这些事件输出未提供可归档的质检附件引用。 | 需要确定质检文件与交接附件的来源、权限和事件关联；质量类型不能替代质检凭证。 |

以上依据见 [收货输出模型](../../WMS/WMS/src/main/java/com/mt/wms/stockin/StockinModels.java)、[收货查询与写入](../../WMS/WMS/src/main/java/com/mt/wms/stockin/StockinRepository.java)、[收货表](../../WMS/WMS/database/migrations/V009__stockin_orders.sql)、[发运输出模型](../../WMS/WMS/src/main/java/com/mt/wms/stockout/StockoutModels.java)、[发运查询与写入](../../WMS/WMS/src/main/java/com/mt/wms/stockout/StockoutRepository.java)、[发运事务](../../WMS/WMS/src/main/java/com/mt/wms/stockout/StockoutService.java) 和 [发运表](../../WMS/WMS/database/migrations/V010__stockout_orders.sql)。

## 建议实施顺序

1. 核实可用联调环境与版本，明确公司、仓库、货主到 TRUST 归属范围的映射。确定货品单位和稳定来源事件号规则，不统一写死为“吨”。
2. 在 WMS 收货、实际发运的库存事务内，同时写入待发送事件表，固化源记录 ID、真实批次、数量/单位、操作身份、业务时间和关联键；事务回滚时不留下待发送记录。
3. 独立发送器上传证据并调用 TRUST API，记录接收回执与后续存证状态。网络或链故障进入待办及重试，保留 WMS 原审批与校验，不增加现场作业的同步上链依赖。
4. TRUST 按归属、来源和源事件号幂等接收。内容相同复用结果，内容不同报告冲突；补正追加新版本，发送器不能在重试时重新拼接当前主数据改变原事件。
5. 验证同一来源批次分两次实际发运、来源与发运相互追溯、断网重试、重复发送、单位/批次缺失、跨范围拒绝和文件核验。再按业务事实扩展质检、过磅、移库等事件。

## 开工条件与验收输出

| 条件 | 需要的具体输入或结果 |
|---|---|
| 环境 | 运行版本、受控测试入口、允许使用的数据范围和账号；配置保存在私有目录。 |
| 来源契约 | 事件类型、稳定事件号、归属映射、实际批次、数量单位、操作身份、业务时间与更正规则。 |
| 发运数据 | SHIP 到 allocation、库存批次和收货来源的可验证关联；缺少关联时明确反馈，不能补猜。 |
| 证据 | 质检/交接文件的实际来源、读取授权、引用规则；暂未提供时显示无证据，不能伪造凭证。 |
| 验收 | 从 WMS 实际业务操作生成事件，经 TRUST 可靠接收、IPFS 归档和 Fabric 存证后可反查源记录；故障恢复后无丢失、无重复业务事件。 |

这是一份接入准备建议，尚未冻结 WMS 对外接口，也未将六系统正式接入标记为完成。对应需求范围为 REQ-TR-001/002/003/004/027/028/031/045/049。
