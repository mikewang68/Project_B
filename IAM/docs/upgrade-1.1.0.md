# IAM 1.1.0 升级与对接

本说明描述通用升级流程，不携带现场账号、服务凭据或部署状态。产品版本 1.1.0 与统一身份断言协议版本分别维护。

## 源码与构建

先保存未提交工作并建立备份分支，合并 IAM 模块源码。使用 Java 17 执行 `mvn -f backend/pom.xml test package`；在 IAM 目录执行 `pnpm --ignore-workspace install --frozen-lockfile` 和 `pnpm --ignore-workspace run build`。前后端一起发布，不能用旧的前端权限快照代替当前后端授权。

## 数据库顺序

1. 备份目标库、当前制品和私有配置；在独立数据库副本验证升级。
2. 已有环境先核对 002–032 中实际需要的身份、导航、短票及权限目录前置表。不要重跑种子覆盖用户、角色、权限分配或已审核菜单。
3. 在 IAM 身份库按顺序执行 `backend/db/isolated/033-explicit-application-boundaries.sql`、`034-scs-operation-permissions.sql`、`035-native-operation-permissions.sql`、`036-native-authority-aliases.sql`，记录脚本摘要及结果。
4. 033 创建角色系统范围、管理对象归属与迁移标记。首次回填属于迁移兼容处理；运行时范围必须来自显式记录，不能继续按角色名称或权限前缀推断。管理员访问级别需明确设为 `ADMIN`，业务角色为 `BUSINESS`，不能把首次默认值当作最终账号授权。
5. 未知历史用户和角色保留 `GLOBAL` 归属。明确审核需要交给 IAM 专用管理员的对象，逐项登记，禁止将全部历史对象划给 IAM。
6. 034–036 登记操作权限和别名，不代表自动授予任意账号这些权限。按实际工作内容授予，导出、审批、执行分别配置。

`IamMigration` 基础命令仍只处理 002、004、005，并校验摘要；不会自动执行上述集成增量。增量由授权迁移操作单独执行，应用启动不自动执行 DDL。

## 对接契约

角色系统范围使用 WMS、PSMS、SCS、EHMS、EMCS、TRUST、IAM、SYS 标准编码。导航返回可信 `allowedAppCodes`，短票与中央会话查询针对目标应用重新计算当前权限、只读状态、系统管理员标志和授权版本。消费方不能凭角色名、本地同名用户或浏览器权限头提权。

每个消费系统使用独立 `X-SSO-Service-Token`，仅准许相应受众。服务凭据登记在 `app.sso.service-tokens`，撤销回调登记在 `app.sso.logout-endpoints`；凭据、回调与目标身份映射必须一致。配置中的发行方、受众、允许回调和应用路径由服务端登记，不能接收任意客户端跳转地址。

IAM 管理前端使用原生 Cookie 恢复身份，写请求使用 `X-IAM-CSRF`。密码、长期令牌及实际短票不能作为浏览器跨域跳转参数。

## 切换与回退

先验证平台管理员、只读账号、IAM 专用管理员及查询角色。重点检查专用账号只看见 IAM；拒绝跨系统对象改密、授予平台超级角色和扩大自身系统范围；禁用、撤权与退出后旧会话失效。

验证后切换制品及配置。失败时恢复对应制品和配置，保留兼容新增表列；如果旧制品不支持范围隔离，应暂停相关专用账号或入口。不要通过删表、清空用户或覆盖共享数据库回滚。真实配置、验收证据和账号材料只保存在私有目录。
