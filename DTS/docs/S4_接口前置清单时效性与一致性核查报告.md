## 2. 当前 DTS 的理解（系统定位与真实状态）

### 2.1 系统定位

DTS（数字孪生可视化系统，S4）是基于 **Vue 3 + TypeScript + Vite + CesiumJS** 的三维可视化前端，当前交付三个页面：

| 页面 | 路由 | 状态 |
|---|---|---|
| 三维作业台 | `/` | 已实现（本地 mock） |
| 综合态势大屏 | `/bigscreen` | 已实现（本地 mock） |
| 落位校核 | `/calibration` | 已实现 |

### 2.2 数据策略（关键事实）

- **现阶段全部数据为本地 mock / 演示**：设备、人员、告警、工单、库存、KPI、能耗均由 `MockDataService`、`alertStore`、`mockData.ts` 等本地模块生成，界面标注"本地模拟 / 推断数据"。
- **REST / WebSocket 仅为预留封装，零业务调用**：
  - `restClient.ts` 已封装（base URL `/api/v1`、OpenAPI 3.1 约定），但全工程**无任何业务代码调用**；
  - `wsClient.ts` 已封装，但 `WS_URL` 为空、**未建立任何真实连接**。
- **无任何现场设备直连**：全工程检索无 OPC UA、Modbus、PLC 直连、设备侧 MQTT、RTSP 等代码。
- **无任何视频组件**：检索 `video / 摄像头 / stream / WebRTC / HLS / ZLMediaKit` 均无实现，当前连视频占位画面都没有。
- mock 设备仅 **3 台龙门吊（CR-01/02/03）**；煤灰线设备未进入生产 mock，筒仓尺寸为比例推断。

### 2.3 工程完整性（重要归档事实）

- `Project_B/DTS` 是**不完整的归档副本**：源码（src）、资源（public/models、cesium、data）、文档、部署脚本齐全，但**缺少工程构建文件**——根 `package.json / pnpm-lock.yaml / pnpm-workspace.yaml`，以及 `apps/admin` 的 `package.json / vite.config.ts / index.html`。
- 部署说明（2026-09-02）§2.1 已记录该缺失；这些文件**从未被 git 跟踪**（DTS 仅一个 Initial commit）。
- 完整可构建的工程文件保留在旧本地副本 `dt-system`（**仅作参考，不用来覆盖 Project_B/DTS**）。
- 结论：当前 Project_B/DTS 副本**无法直接 `pnpm install / build`**，需在正式接入阶段从 `dt-system` 回迁构建文件（回迁动作不在本核查任务范围，建议单独立项）。
