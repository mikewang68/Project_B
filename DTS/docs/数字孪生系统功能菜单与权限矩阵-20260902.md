## 一、权限设计规范

### 1.1 权限编码规则

```
dt:<模块编码>:<菜单编码>:<操作类型>
```

- 模块编码：`twin`（三维作业台）、`screen`（大屏）、`calib`（落位校核）、`device`（设备）、`alert`（告警）、`task`（作业调度）、`stock`（库存）、`system`（系统管理）。
- 操作类型统一枚举：

| 操作 | 含义 | 典型按钮 |
|---|---|---|
| `view` | 查看/访问（菜单可见、列表可读、详情可读） | 进入模块、查询、查看详情 |
| `add` | 新增 | 新建、添加、导入 |
| `edit` | 编辑/修改 | 修改、保存配置、启用/禁用 |
| `delete` | 删除 | 删除、作废、取消 |
| `execute` | 执行类操作（不可回滚或影响现场） | 下发任务、远程控制、演示、重置、校准应用 |
| `approve` | 审批 | 审核、驳回 |
| `export` | 导出 | 导出 Excel/PDF、截图 |
| `import` | 导入 | 批量导入 |

### 1.2 权限判定原则

1. **菜单访问**：用户拥有某菜单的 `view` 权限，左侧菜单/路由才可见可进；无 `view` 则路由直接 403。
2. **按钮级**：页面内每个操作按钮绑定一个权限编码，无权限则隐藏或禁用。
3. **写操作默认需 `view` 前置**：拥有 `add/edit/delete/execute` 必然同时拥有 `view`，授权时由后端自动补全。
4. **高危操作二次确认**：`execute`（远程控制、校准应用、资产替换）和 `delete` 在前端必须二次确认，后端记录操作日志。
5. **数据范围**：本清单只定义功能权限；数据级权限（如某调度员只能看自己班组的任务）由后端数据权限另行控制。

## 六、前端落地建议

### 6.1 权限存储与获取

- 登录后后端返回该用户的权限编码列表（如 `["dt:twin:scene:view","dt:twin:device:view",...]`），存入 Pinia（`useAppStore` 或新建 `usePermissionStore`）。
- 提供全局判断函数：

```ts
// src/permissions/index.ts（建议新增）
export function hasPerm(code: string): boolean {
  return usePermissionStore().codes.includes(code)
}
export function hasAnyPerm(codes: string[]): boolean {
  return codes.some(hasPerm)
}
```

### 6.2 路由级（菜单访问）

在 `src/router/index.ts` 的全局前置守卫中，对每个路由的 `meta.perm` 做校验：

```ts
// router 示例
{
  path: '/calibration',
  component: () => import('@/views/CalibrationView.vue'),
  meta: { title: '落位校核', perm: 'dt:calib:view' },
}
// 守卫
router.beforeEach((to) => {
  if (to.meta.perm && !hasPerm(to.meta.perm as string)) {
    return { path: '/403' }
  }
})
```

左侧菜单根据用户权限过滤后渲染（无 `view` 的菜单不显示）。

### 6.3 按钮级（增删改查执行）

自定义指令 `v-perm`，无权限时移除按钮：

```ts
// main.ts 注册
app.directive('perm', {
  mounted(el, binding) {
    if (!hasPerm(binding.value)) el.parentNode?.removeChild(el)
  },
})
```

页面使用：

```vue
<el-button v-perm="'dt:task:job:execute'" type="primary" @click="dispatch">下发任务</el-button>
<el-button v-perm="'dt:calib:asset:execute'" @click="replaceModel">替换模型</el-button>
```

### 6.4 高危操作二次确认

对 `execute` / `delete` 类按钮，点击后弹 `ElMessageBox.confirm`，确认后才调用接口，并在成功回调里提示"操作已记录到操作日志"。

## 七、后端接口鉴权建议

- 每个 REST 接口（当前 `restClient` 走 `/api/v1`）在网关注册时绑定权限编码，Easegress 或后端网关层校验用户 token 中的权限列表。
- 接口与权限编码一一对应，例如：
  - `GET /api/v1/devices` → `dt:device:ledger:view`
  - `POST /api/v1/devices` → `dt:device:ledger:add`
  - `PUT /api/v1/devices/{id}` → `dt:device:ledger:edit`
  - `DELETE /api/v1/devices/{id}` → `dt:device:ledger:delete`
  - `POST /api/v1/tasks/{id}/dispatch` → `dt:task:job:execute`
- 所有写操作（add/edit/delete/execute/approve）必须写入操作日志（用户、时间、模块、操作、目标、结果、IP）。
- WebSocket 实时推送（`wsClient`）按用户数据范围过滤，不越权推送。
