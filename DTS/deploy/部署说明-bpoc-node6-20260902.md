# B 项目数字孪生前端 · bpoc-node6 部署说明（2026-09-02）

> 目标：把现有 Vue3 + Cesium 演示工程构建为**纯静态包**，直接发布到开发服务器
> **bpoc-node6 的 Nginx 1.24**，并通过 Nginx 反代与 node4/node5 的 Easegress 网关联调。
> 适配环境：openEuler 24.03 LTS-SP3、Node.js 24.18、pnpm 10.34.5（见《开发服务器已安装技术栈现状清单 v1.0》）。

---

## 1. 为什么这样改（适配结论）

服务器对前端的定位是 **Nginx 静态发布**（node6），不需要 Node 常驻进程。本次改造只做"部署适配"，不改动任何三维业务逻辑：

| 适配项 | 改造前 | 改造后 |
|---|---|---|
| 资源根路径 | 硬编码 `/models` `/data` `/cesium` | 统一跟随 Vite `base`，根路径/子路径都能跑（`src/config/runtime.ts`） |
| 后端地址 | 硬编码 `/api/v1` | `VITE_API_BASE_URL` 可配，默认同源，由 Nginx 反代 Easegress |
| 构建 base | 固定 `/` | 默认 `/`，`--base=/dt/` 可切子路径 |
| 锁文件 | pnpm7 的 lockfileVersion 5.4 | 用 **pnpm 10.34.5** 重生成，服务器 `--frozen-lockfile` 可直接装 |
| 依赖 | 含未使用的 `three` | 已移除，减小安装/构建面 |
| 构建产物 | 单块 4.1MB chunk | Cesium/ECharts/Element/Vue 手动分包，利于缓存 |
| 运行版本约束 | node>=20 | 标注 node>=20.19、pnpm>=9（对齐 Node24/pnpm10） |
| 交付物 | 无 | `deploy/` 下 Nginx 配置 + 一键脚本 |

> 已做 Linux 兼容校验：全部 69 条本地/别名 import 路径大小写与实际文件完全一致，openEuler 区分大小写的文件系统不会出现"Windows 能跑、Linux 404"。

## 3. 在 node6 上构建并发布（推荐，最简路径）

```bash
# 1) 拉取/上传源码到 node6，例如 /opt/src/dt-system
cd /opt/src/dt-system

# 2) 一键脚本：装依赖 → 类型检查 → 构建 → 同步到 Nginx 目录 → reload
chmod +x deploy/build-and-deploy.sh
./deploy/build-and-deploy.sh
```

脚本默认把 `apps/admin/dist` 同步到 `/usr/share/nginx/b-dt`，可用环境变量覆盖：

```bash
WEB_ROOT=/usr/share/nginx/html/b-dt ./deploy/build-and-deploy.sh   # 改发布目录
BASE=/dt/ ./deploy/build-and-deploy.sh                             # 子路径部署
```

## 4. 手动分步（需要精细控制时）

```bash
cd /opt/src/dt-system

# 安装依赖（严格按锁文件，保证可重复）
pnpm install --frozen-lockfile

# 生产构建（根路径）
pnpm build
# —— 若 Nginx 挂在子路径 /dt/：
# pnpm --filter admin build -- --base=/dt/

# 发布静态包
sudo mkdir -p /usr/share/nginx/b-dt
sudo rsync -a --delete apps/admin/dist/ /usr/share/nginx/b-dt/

# 安装 Nginx 站点配置
sudo cp deploy/nginx-bpoc-node6.conf /etc/nginx/conf.d/b-dt.conf
sudo nginx -t && sudo systemctl reload nginx
```

## 5. Nginx 配置要点（deploy/nginx-bpoc-node6.conf）

- `root /usr/share/nginx/b-dt;` 指向 dist。
- **SPA 回退**：`try_files $uri $uri/ /index.html;`（vue-router history 模式必需，否则刷新 /bigscreen 404）。
- **接口反代**：`location /api/ { proxy_pass http://b_dt_api; }`，上游 `upstream b_dt_api` 里把占位 `127.0.0.1:8080` 改成 **node4/node5 Easegress 的真实 IP:端口**（两处 TODO）。
- gzip、`assets` 长缓存、`cesium/models/data` 7 天缓存、`index.html` 不缓存。
- 子路径部署的改法写在配置文件末尾注释里（构建加 `--base=/dt/` + `alias` 段）。

## 6. 与后端链路联调

当前页面数据为**本地 mock**，可独立演示，不依赖后端。接入数据底座时：

- 生产：前端请求同源 `/api/v1/...` → Nginx → Easegress（node4/5）→ openGauss/Kvrocks/RocketMQ/openGemini。只需改 Nginx upstream，无需重新构建前端。
- 若要前端直连网关完整地址：构建前设置 `VITE_API_BASE_URL=http://<网关IP:端口>/api/v1`。
- 本地开发：`pnpm dev` 时 `/api` 由 Vite 代理到 `.env.development` 的 `VITE_DEV_API_TARGET`。
- WebSocket（实时推送）：配置 `VITE_WS_URL`，并打开 Nginx 配置里被注释的 `/ws/` 段。

## 8. 离线/内网环境安装依赖（若 node6 无法访问公网 npm）

三选一：
1. **内网 npm 镜像/私服**：`pnpm config set registry http://<内网镜像>/` 后再 install；可写入 `~/.npmrc`。
2. **离线依赖包**：在同架构、能联网的机器执行 `pnpm fetch`（或 `pnpm install --frozen-lockfile` 后打包 `node_modules`），随源码一起拷贝到 node6。
3. **直接传产物**：在本地 `pnpm build` 后只把 `apps/admin/dist` 用 `deploy/deploy-rsync.sh` 或 scp 传到 node6，node6 无需安装 Node 依赖（Nginx 只托管静态文件）。**这是最省事、对服务器要求最低的方式。**

## 9. 常见问题

- **页面打开空白、F12 看到资源 404**：99% 是 base 与 Nginx 路径不一致。根路径用默认构建；子路径必须 `--base=/子路径/` 且 Nginx 用 alias，两边一致。
- **刷新子路由 404**：缺 SPA `try_files` 回退。
- **Cesium 报 worker/资源加载失败**：确认 `dist/cesium` 已同步且 Nginx 能 200 访问；路径由 `CESIUM_BASE_URL` 自动跟随 base。
- **`pnpm install --frozen-lockfile` 报 lock 不匹配**：本地改动了依赖却没用 pnpm10 更新锁；在装有 pnpm10 的环境执行 `pnpm install` 重新生成并提交 `pnpm-lock.yaml`。
- **GLB 被浏览器缓存**：模型清单带 `?layout=...` 版本参数，换模型时同步修改 `modelManifest.ts` 的 `ASSET_VERSION`。
- **端口/防火墙**：openEuler firewalld 需放行 Nginx 端口（默认 80）：`sudo firewall-cmd --permanent --add-service=http && sudo firewall-cmd --reload`。
