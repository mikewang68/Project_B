# WMS 源码更新与对接

本包交付仓储系统的 IAM V2.1 接入与业务动作修复。版本、分支及提交号见总 README。
请逐文件三方合并，保留自己分支已有入出库、费用、安卓及 joint-inbound 修改。
源码增量放回完整仓库编译；不要整目录覆盖现有项目。

## 需要合并的内容

- `WMS/src`：SSO 兑换、会话撤销、实时中央权限和原生业务权限交集。
- 仓库作为范围根；列表、详情、统计、导出和写入同时执行公司、仓库、货主及中央范围限制。
- 入出库确认、内部费用处理、XLSX 导出等动作使用对应权限，确认不依赖普通编辑权限。
- 人员页将受管账号管理引导到 IAM；V2 用户不能绕过 IAM 修改原生人员权限。
- agent 计划保存可信主体与会话引用，每次巡检执行重新校验当前授权。
- 前端同步按钮、权限刷新、人员页及既有入站联动的兼容处理。

## 公共依赖

WMS 已将 `IAM/context-client` 的 `2.1.0` 源码内嵌至 `WMS/src/main/java/com/bproject/iam/context`。
合并时保留整组内嵌类，与公共 SDK 同步，不要再加入同名 Maven 类导致冲突。
仓库中的 `IAM/context-client` 用作契约来源；其余项目的依赖安装方式不直接套用 WMS。
同时保留 PSMS 共享派单适配和原有本地主体映射实现。

## 构建

实验室环境使用 Java `17`、Maven，以及 Node `>=24.11.1 <25`、pnpm `>=10.34.5 <12`。
完整仓库根目录执行：

```sh
cd WMS
mvn clean package
cd ..
```

从 WMS 目录执行 Maven，以正确解析 `.mvn/maven.config` 引用的本模块设置。Maven 生命周期会安装前端锁定依赖，并自动执行 `typecheck`、`test:unit`、`build`。
产物是 `WMS/target/mt-wms.jar`；不要再把另一版本前端覆盖进这个构建。
若单独调试前端，可在 `WMS/frontend` 运行：

```sh
pnpm install --frozen-lockfile
pnpm run verify-and-build
```

测试连接使用专门测试配置；不得将会重置数据的集成测试指向共享业务库。

## 数据库与配置

先核对已有结构及迁移台账，再依次检查 `WMS/db/v21` 的 `001`、`002`、`003`。
`001` 补仓库归属及异步任务身份引用；`002` 补 agent 授权引用。
`003` 扩展 IAM 受管角色的原生技术上限，必须先确认映射主体均为 V2；实际权限仍取交集。
保留 `WMS/database/migrations/V016__psms_inbound.sql` 与前序业务迁移；已执行项不重复套用。

| Spring 配置项 | 填写规则 |
|---|---|
| `wms.sso.enabled` | 完成登记后设为 `true` |
| `wms.sso.iam-base-url` | `<IAM地址>/api/v1/iam` |
| `wms.sso.service-token` | 受保护配置注入 |
| `wms.sso.audience` | `wms` |
| `wms.sso.exchange-allowed-cidrs` / `trusted-proxies` | 仅登记实际受信调用方 |
| `wms.shared-dispatch.enabled` / `base-url` | 按已登记共享派单入口配置 |

保留原用户 ID、公司/仓库/货主关系及 `wms_sso_subject_map`；区域编码不能替代公司编码。
新范围必须先建立可信仓库归属和原生映射，未知历史不自动认领。

## 更新后的最小检查

1. 门户登录后读取仓库和库存，中央范围与原生业务范围均有效。
2. 跨项目、区域、仓库或货主的列表、详情、导出和写入被拒绝。
3. 检查一个入库和出库样本，独立核对 `CONFIRM` 与普通编辑的授权差异。
4. 只读账号允许已获权导出，但不能通过原生接口或 agent 绕过写限制。
5. 撤销岗位后，页面请求和下一次巡检均拒绝；统一退出使旧会话失效。
6. 保留并检查 PSMS 入站幂等、重复提交、状态回传与本分支现有业务功能。
